# FFI and native assets

Calling C (and C++) code from Dart: shipping the native library as a code asset built by hooks, and generating the Dart bindings with `package:ffigen`. Under Dart's native assets feature (build hooks, stable since Dart 3.10), a package's `hook/build.dart` compiles or downloads the native library for each target, and `dart run`, `dart test`, `dart build` and `flutter run` bundle it automatically. Two rules recur through the dart-lang FFI skills: whether bindings are generated from headers (never hand-written), and whether the build uses `dart build` (which runs hooks) rather than `dart compile exe` (which fails when hooks are present). Compiling CLIs is in [CLI-APPS.md](CLI-APPS.md); pubspec fields in [PACKAGES.md](PACKAGES.md); Flutter plugins in [flutter SKILL.md](https://github.com/Quegenx/agent-skills/blob/main/skills/mobile/flutter/SKILL.md).

## How it works

- **Two hooks in `hook/`:** `hook/build.dart` compiles local C sources or bundles prebuilt binaries per host and target architecture; `hook/link.dart` (optional) links code assets with tree shaking to strip unused native symbols. `dart` and `flutter` invoke them.
- **Hook dependencies must be normal dependencies,** not dev_dependencies.
- **Tree shaking** needs a record-use mapping, generated by ffigen, from Dart method names (`Method.name`) to C symbols. The link hook reads which methods the app actually calls from `input.recordedUses` (`@RecordUse()` from package:meta plus package:record_use, Dart 3.13).

| Package | Purpose | Key APIs |
|---|---|---|
| `package:hooks` | Orchestrator | `build(args, callback)`, `link(args, callback)` |
| `package:native_toolchain_c` | Detects compilers (MSVC, Xcode/Clang, GCC), runs toolchains | `CLibrary`, `CBuilder`, `LinkerOptions.treeshake` |
| `package:code_assets` | Code metadata records for dynamic loaders | `CodeAsset`, `DynamicLoadingBundled` |

## Rules

- **Resolve files platform-independently:** never hardcode absolute paths, shell scripts or system command variables; use `Platform.script.resolve()` or `Uri` resolution.
- **Build through `package:native_toolchain_c`** (`CBuilder`, `CLibrary`); never invoke raw `gcc`, `clang` or `msvc` through a shell.
- **Every handcrafted and generated source file** (bindings, helpers, hooks) carries the package's copyright and license header.
- **Name the record-use mapping** as a `.g.dart` under `lib/src/third_party/` (for example `sqlite3.record_use_mapping.g.dart`).
- **Precompiled downloads:** verify them against a lookup table of MD5 or SHA-256 hashes and provide an offline fallback (a local compile behind a flag like `local_build`).
- **Never hand-write bindings** when `.h` headers exist or can be generated (see ffigen below).

## Setup

```bash
dart pub add code_assets hooks native_toolchain_c record_use dev:ffigen
```

```yaml
dependencies:
  code_assets: ^1.0.0
  hooks: ^0.1.0
  native_toolchain_c: ^0.1.0
  record_use: ^0.6.0

dev_dependencies:
  ffigen: ^20.1.1
```

Then: a shared C spec in `lib/src/c_library.dart`; `hook/build.dart` and `hook/link.dart`; `dart test` runs the hook lifecycle.

**Host toolchains (Method 1):**

| Host | Install |
|---|---|
| macOS | Xcode Command Line Tools: `xcode-select --install` |
| Linux | GCC or Clang: `sudo apt install build-essential` |
| Windows | Visual Studio Installer, workload "Desktop development with C++" |

With no toolchain on the path, the build hook throws a compilation exception.

## Choose an approach

| Aspect | Method 1: local compile plus tree shaking (recommended) | Method 2: precompiled downloads |
|---|---|---|
| Use case | C/C++ source in the package, maximum size optimization | Local compile slow or complex, or avoid the host toolchain |
| Toolchain | Requires Xcode tools, MSVC or GCC | None |
| Binary optimization | Unused symbols tree-shaken | Shipped as is |
| Offline | Fully offline | Needs network, with an offline fallback |
| Reference | The SQLite pattern under `pkgs/code_assets/example/sqlite` | The `download_asset` hook package |

Method 2's case: the host may lack compilers, downloads "execute in milliseconds" against multi-minute compiles, and it avoids cross-compiling constraints.

## Method 1: compile locally and tree-shake

Header `third_party/sqlite/sqlite3.h`:

```c
#ifndef SQLITE3_H_
#define SQLITE3_H_

const char *sqlite3_libversion(void);

#endif // SQLITE3_H_
```

The mapping `lib/src/third_party/sqlite3.record_use_mapping.g.dart`, generated by `tool/ffigen.dart` alongside the bindings `lib/src/third_party/sqlite3.g.dart`:

```dart
// AUTO-GENERATED FILE - DO NOT MODIFY.
// Generated via ffigen.

const recordUseMapping = {
  'sqlite3_libversion': 'sqlite3_libversion',
};
```

`lib/src/c_library.dart`:

```dart
import 'package:native_toolchain_c/native_toolchain_c.dart';

/// The C build specification for the sqlite library.
final cLibrary = CLibrary(
  name: 'sqlite3',
  assetName: 'src/third_party/sqlite3.g.dart',
  sources: ['third_party/sqlite/sqlite3.c'],
);
```

`hook/build.dart` (builds the `.so`, `.dylib` or `.dll`):

```dart
import 'package:code_assets/code_assets.dart';
import 'package:hooks/hooks.dart';
import 'package:sqlite/src/c_library.dart';

void main(List<String> args) async {
  await build(args, (input, output) async {
    if (input.config.buildCodeAssets) {
      await cLibrary.build(
        input: input,
        output: output,
        defines: {
          if (input.config.code.targetOS == OS.windows)
            // Ensure C functions are explicitly exported in the Windows DLL
            'SQLITE_API': '__declspec(dllexport)',
        },
      );
    }
  });
}
```

`hook/link.dart`:

```dart
import 'package:hooks/hooks.dart';
import 'package:native_toolchain_c/native_toolchain_c.dart';
import 'package:record_use/record_use.dart';
import 'package:sqlite/src/c_library.dart';
import 'package:sqlite/src/third_party/sqlite3.record_use_mapping.g.dart';

void main(List<String> arguments) async {
  await link(arguments, (input, output) async {
    await cLibrary.link(
      input: input,
      output: output,
      linkerOptions: LinkerOptions.treeshake(
        // Map Dart Method references back to raw C symbol names
        symbolsToKeep: input.recordedUses?.calls.keys.cast<Method>().map(
          (e) => recordUseMapping[e.name]!,
        ),
      ),
    );
  });
}
```

## Method 2: precompiled downloads

The hook checks a `local_build` user define. Otherwise it downloads the binary with `HttpClient`, checks its MD5 against a table, and registers a `CodeAsset`.

`lib/src/hook_helpers/hashes.dart`:

```dart
const assetHashes = {
  'libnative_add_macos_arm64.dylib': '4a88f50438a98402db2dbd47b59eb412',
  'libnative_add_linux_x64.so': '9f5e15043aa98402dcdbbd47b59ea520',
  'native_add_windows_x64.dll': 'a881e5043ba98402acdebd47b59fa321',
};
```

`lib/src/hook_helpers/download.dart`:

```dart
import 'dart:io';
import 'package:code_assets/code_assets.dart';
import 'package:crypto/crypto.dart';

const version = '1.0.0';

Uri downloadUri(String target) => Uri.parse(
  'https://github.com/my-org/my-native-repo/releases/download/$version/$target',
);

Future<File> downloadAsset(
  OS targetOS,
  Architecture targetArchitecture,
  Directory outputDir,
) async {
  final fileName = targetOS.dylibFileName('native_add_${targetOS.name}_${targetArchitecture.name}');
  final uri = downloadUri(fileName);
  
  final client = HttpClient()..findProxy = HttpClient.findProxyFromEnvironment;
  final request = await client.getUrl(uri);
  final response = await request.close();
  
  if (response.statusCode != 200) {
    throw ArgumentError('Download target $uri failed: Code ${response.statusCode}');
  }
  
  final targetFile = File.fromUri(outputDir.uri.resolve(fileName));
  await targetFile.create(recursive: true);
  await response.pipe(targetFile.openWrite());
  
  return targetFile;
}

Future<String> hashAsset(File file) async {
  return md5.convert(await file.readAsBytes()).toString();
}
```

`hook/build.dart`:

```dart
import 'dart:io';
import 'package:code_assets/code_assets.dart';
import 'package:hooks/hooks.dart';
import 'package:my_download_package/src/hook_helpers/hashes.dart';
import 'package:my_download_package/src/hook_helpers/download.dart';
import 'package:native_toolchain_c/native_toolchain_c.dart';

void main(List<String> args) async {
  await build(args, (input, output) async {
    final localBuild = input.userDefines['local_build'] as bool? ?? false;

    if (localBuild) {
      final name = 'native_add_${input.config.code.targetOS.name}_${input.config.code.targetArchitecture.name}';
      final builder = CBuilder.library(
        name: name,
        assetName: 'native_add.dart',
        sources: ['src/native_add.c'],
      );
      await builder.run(input: input, output: output);
    } else {
      final targetOS = input.config.code.targetOS;
      final targetArch = input.config.code.targetArchitecture;
      final outputDir = Directory.fromUri(input.outputDirectory);

      final file = await downloadAsset(targetOS, targetArch, outputDir);

      final fileHash = await hashAsset(file);
      final expectedFileName = targetOS.dylibFileName('native_add_${targetOS.name}_${targetArch.name}');
      final expectedHash = assetHashes[expectedFileName];

      if (fileHash != expectedHash) {
        throw Exception(
          'Security Mismatch: File $expectedFileName hash verification failed! '
          'Found hash: $fileHash, expected: $expectedHash.'
        );
      }

      output.assets.code.add(
        CodeAsset(
          package: input.packageName,
          name: 'native_add.dart',
          linkMode: DynamicLoadingBundled(),
          file: file.uri,
        ),
      );
    }
  });
}
```

**User defines** go in the pubspec of the package or the workspace root:

```yaml
hooks:
  user_defines:
    <your_package_name>:
      local_build: true
```

## Generating bindings with ffigen

- **Hand-written FFI bindings are "error-prone, brittle, and highly discouraged".** If `.h` headers exist or are generated, never write manual `DynamicLibrary.lookup`, `@Native` externals or raw struct classes; use `FfiGenerator`. The skill's "BEFORE: Manual FFI Binding (The Anti-Pattern)", which it calls "fragile, blocks tree-shaking metadata, and is highly prone to ABI and structural mapping issues":

```dart
// lib/src/sqlite3_manual.dart
import 'dart:ffi' as ffi;
import 'package:ffi/ffi.dart';

// Flaw 1: Hardcoded DynamicLibrary lookup blocks integration with modern native asset compilation.
final ffi.DynamicLibrary _dylib = ffi.DynamicLibrary.open('libsqlite3.so');

// Flaw 2: Manual function type matching requires writing redundant dynamic lookup boilerplate and lacks tree-shaking metadata.
typedef _sqlite3_libversion_C = ffi.Pointer<ffi.Char> Function();
typedef _sqlite3_libversion_Dart = ffi.Pointer<ffi.Char> Function();

final _sqlite3_libversion_Dart sqlite3LibVersion = _dylib
    .lookup<ffi.NativeFunction<_sqlite3_libversion_C>>('sqlite3_libversion')
    .asFunction();
```

Its AFTER is the `tool/ffigen.dart` below.
- **The generator lives at `tool/ffigen.dart`.**
- **Headers:** third-party headers in `third_party/`; otherwise `src/` at the package root is acceptable; if they are elsewhere, tell the user to move them (for example to `third_party/`).
- **Include precisely:** use positive inclusion lists (`Functions.includeSet` or `include` closures); don't import a whole library unless needed.
- **Output:** bindings for third-party libraries go under `lib/src/third_party/`, the primary file ending in `.g.dart` (for example `sqlite3.g.dart`).
- **Always set `preamble`** in `Output`: a license matching the native library, the native header's copyright, and a generation warning (for example `// Generated by package:ffigen. Do not edit manually.`).
- **With native hooks:** `recordUse: (_) => true` under `Functions`, and `recordUseMapping` in `Output` as a `.g.dart` under `lib/src/third_party/`.
- **Before finishing:** run the generator, check for changed output, and always run `dart analyze`.

**API** (`package:ffigen/ffigen.dart`). Everything except `headers` and `integers` defaults to `excludeAll`, and `output` is required:

```dart
FfiGenerator({
  Headers headers = const Headers(),
  Enums enums = Enums.excludeAll,
  Functions functions = Functions.excludeAll,
  Globals globals = Globals.excludeAll,
  Integers integers = const Integers(),
  Macros macros = Macros.excludeAll,
  Structs structs = Structs.excludeAll,
  Typedefs typedefs = Typedefs.excludeAll,
  Unions unions = Unions.excludeAll,
  UnnamedEnums unnamedEnums = UnnamedEnums.excludeAll,
  ObjectiveC? objectiveC,
  required Output output,
}).generate();
```

| Class | Options |
|---|---|
| `Headers` | `entryPoints` (list of header `Uri`); `include` (`bool Function(Uri header)` for transitive headers); `compilerOptions` (flags to libclang); `ignoreSourceErrors` (`true` silences errors in third-party headers) |
| `Functions` | `include` (for example `(decl) => {'my_func'}.contains(decl.originalName)` or `Functions.includeSet({'my_func'})`); `isLeaf` (`(decl) => true` for functions that don't call back into Dart or block the thread); `recordUse` (`(_) => true`, tree-shaking metadata, "essential in `dart-lang/native`") |
| `Output` | `dartFile` (Uri); `recordUseMapping` (Uri); `preamble` (text); `format` (`true` runs the formatter) |

The skill names Objective-C and Swift integrations as in scope (the `objectiveC` parameter) but gives no further detail.

**Workflow:**

1. `dart pub add dev:ffigen` (latest through the Dart MCP server or https://pub.dev/packages/ffigen, for example `^20.1.1`).
2. Resolve paths from `Platform.script`:

   ```dart
   final packageRoot = Platform.script.resolve('../');
   final headerFile = packageRoot.resolve('third_party/library.h');
   final targetBindings = packageRoot.resolve('lib/src/third_party/bindings.g.dart');
   ```
3. Write `tool/ffigen.dart`.
4. `dart run tool/ffigen.dart`.
5. `dart analyze`.

```dart
// Copyright (c) 2025, the Dart project authors.  Please see the AUTHORS file
// for details. All rights reserved. Use of this source code is governed by a
// BSD-style license that can be found in the LICENSE file.

import 'dart:io';
import 'package:ffigen/ffigen.dart';

void main() {
  // Resolve paths dynamically relative to Platform.script
  final packageRoot = Platform.script.resolve('../');
  final entryHeader = packageRoot.resolve('third_party/sqlite/sqlite3.h');
  final bindingsOutput = packageRoot.resolve('lib/src/third_party/sqlite3.g.dart');
  final treeShakeMapping = packageRoot.resolve('lib/src/third_party/sqlite3.record_use_mapping.g.dart');

  FfiGenerator(
    headers: Headers(
      entryPoints: [entryHeader],
    ),
    functions: Functions(
      include: (decl) => {'sqlite3_libversion'}.contains(decl.originalName),
      // Essential for package optimization and tree-shaking
      recordUse: (_) => true,
    ),
    output: Output(
      dartFile: bindingsOutput,
      recordUseMapping: treeShakeMapping,
      format: true,
      preamble: '''

// AUTO-GENERATED FILE - DO NOT MODIFY.
// Generated via ffigen.
// To regenerate: dart run tool/ffigen.dart

// ignore_for_file: type=lint, unused_import, unused_element, deprecated_member_use_from_same_package, experimental_member_use
''',
    ),
  ).generate();

  print('Successfully generated sqlite3 FFI bindings.');
}
```

This produces `lib/src/third_party/sqlite3.g.dart` and `lib/src/third_party/sqlite3.record_use_mapping.g.dart`.

- **Lint warnings in the generated file:** add the codes (for example `camel_case_types`, `non_constant_identifier_names`) to the preamble's `ignore_for_file:`; don't change the global rules.
- **Real compile or analysis errors in generated code:** don't edit the generated file; tell the user to report it at https://github.com/dart-lang/native.

## Building and shipping

- **Use `dart build`, not `dart compile exe`,** once the package or any dependency has build hooks: `dart compile exe` and `aot-snapshot` don't run hooks and fail when hooks are present. `dart build cli` writes `bundle/bin/<compiled_executable>` and `bundle/lib/<dynamic_libraries>` (default output `build/cli/_/`); details are in [CLI-APPS.md](CLI-APPS.md).
- **Outputs during development:** `.dart_tool/resources/` (or the target directories) holds the `.dylib` (macOS), `.so` (Linux) or `.dll` (Windows).
- **No native calls means no library:** if the app uses no native methods, the link hook logs `Skipping linking as no symbols are to be kept.` and no `.dylib`, `.so` or `.dll` is placed in the bundle.

## Changes by version

| Version (date) | Change |
|---|---|
| 3.13 (2026-08-12) | `@RecordUse()` (package:meta) plus package:record_use for native library tree shaking in `hook/link.dart` through `input.recordedUses`; `dart build cli --target-os`/`--target-arch` |
| 3.13.3 (2026-09-01) | Fix for Windows to Linux cross-compilation with link hooks |
| 3.10 (2025-11-12) | Build hooks (formerly native assets) stable; `dart build` |

## Prove it

1. **`dart test`** completes with no runtime or build-tool exceptions.
2. **Outputs:** `.dart_tool/resources/` (or the target directories) contain the `.dylib`, `.so` or `.dll`.
3. **Tree shaking:** run `dart build cli bin/main.dart` and inspect the exports: macOS `nm -gU build/cli/lib/libsqlite3.dylib`; Linux `nm -D build/cli/lib/libsqlite3.so`; Windows (MSVC Developer Command Prompt) `dumpbin /EXPORTS build\cli\lib\sqlite3.dll`. Only the kept entry points (for example `sqlite3_libversion`) appear.
4. **Offline:** set `local_build: true`, disable the network and run `dart test`; it compiles locally with no download attempts.
5. **Bindings:** generated files sit in `lib/src/third_party/` with `.g.dart` names, re-running `dart run tool/ffigen.dart` changes nothing, and `dart analyze` reports zero errors or warnings.
