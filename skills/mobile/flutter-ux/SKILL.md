# Flutter UX

This skill holds community tips, not Flutter team guidance: FlutterPro tips by Kamran Bekirov ([FlutterPro](https://flutterpro.design)), ApparenceKit tips and blog posts ([ApparenceKit](https://apparencekit.dev)) and Kamran Bekirov's design-review skill ([improve-design](https://github.com/kamranbekirovyz/skills/tree/main/flutter-improve-design)). Most of it is the polish an app needs after it works: the keyboard closes when the user is done, lists leave room above the system bar, images hold their space and fade in, numbers and dates read the way the user's region writes them, and taps answer with motion and a haptic. The official guidance (architecture, layout, routing, accessibility, performance, versions) is [../flutter/SKILL.md](../flutter/SKILL.md), and it wins on correctness: where a tip differs from it, the topic file states both sides and tags each. Custom render objects are [../flutter-render-objects/SKILL.md](../flutter-render-objects/SKILL.md); the Dart language is [../dart/SKILL.md](../dart/SKILL.md); framework-neutral durations and curves are [../../frontend/ui-animation/SKILL.md](../../frontend/ui-animation/SKILL.md).

## The rules

1. **Close the keyboard when the user is done:** `keyboardDismissBehavior: ScrollViewKeyboardDismissBehavior.onDrag` on scrollables with fields (chat screens stay `manual`), and `FocusManager.instance.primaryFocus?.unfocus()` before opening any modal, not `FocusScope.of(context).unfocus()` [FlutterPro](https://flutterpro.design/details/dismiss-keyboard-on-scroll) [FlutterPro](https://flutterpro.design/details/unfocus-before-modal) ([KEYBOARD-AND-FOCUS.md](KEYBOARD-AND-FOCUS.md)).
2. **Give every form a keyboard path:** `textInputAction` `.next` on each single-line field, `.done` (or `.send`, `.go`, `.search`) on the last with the submit in `onFieldSubmitted`, and `autofocus: true` on a page whose only control is one field [FlutterPro](https://flutterpro.design/details/text-input-action) [FlutterPro](https://flutterpro.design/details/autofocus-single-field) ([KEYBOARD-AND-FOCUS.md](KEYBOARD-AND-FOCUS.md)).
3. **Catch paste and autofill in `inputFormatters`:** every edit, typed or pasted, goes through them, so strip a doubled dial code there and block an amount past its limit there instead of erroring afterwards [FlutterPro](https://flutterpro.design/details/autofill-dial-code) [FlutterPro](https://flutterpro.design/details/max-amount-formatter) ([FORMS-AND-INPUT.md](FORMS-AND-INPUT.md)).
4. **Images hold their space and arrive calmly:** size the box before load (`AspectRatio` or width and height; `fit:` doesn't count), show a plain grey box, fade in, and show a subtle broken-image icon on failure, never a technical message; precache the icons the first screen shows during the splash [FlutterPro](https://flutterpro.design/details/reserve-image-space) [FlutterPro](https://flutterpro.design/details/smooth-image-loading) [FlutterPro](https://flutterpro.design/details/precache-icons) ([IMAGES-AND-TYPOGRAPHY.md](IMAGES-AND-TYPOGRAPHY.md), [SCROLLING-AND-LAYOUT.md](SCROLLING-AND-LAYOUT.md)).
5. **Never show raw values:** numbers through `NumberFormat`, dates through `DateFormat`, phone numbers formatted on display and while typing, and one shared guard that turns `null`, `"null"` and empty into "-" or "N/A" [FlutterPro](https://flutterpro.design/details/format-numbers-for-humans) [FlutterPro](https://flutterpro.design/details/format-date-times) [FlutterPro](https://flutterpro.design/details/format-phone-numbers) [FlutterPro](https://flutterpro.design/details/never-show-null) ([FORMATTING.md](FORMATTING.md)).
6. **Make the whole control take the tap and answer it:** `HitTestBehavior.opaque` on a `GestureDetector` whose child has padding or gaps, and a subtle haptic on tab switches, successful submits, errors and toggles [FlutterPro](https://flutterpro.design/details/gesture-detector-hit-area) [FlutterPro](https://flutterpro.design/details/haptic-feedback) ([MOTION-AND-FEEDBACK.md](MOTION-AND-FEEDBACK.md)).
7. **Where a tip disagrees with Flutter's docs, show both.** The text-scale cap (limit it "to x1.1 at max", [FlutterPro](https://flutterpro.design/details/text-scale-factor)) against Flutter's "Make sure your layout has enough room to render all its contents when the font sizes are increased" ([../flutter/ACCESSIBILITY.md](../flutter/ACCESSIBILITY.md#design-values)); bottom padding instead of `SafeArea` on scrollables against `SafeArea` around the body ([../flutter/LAYOUT-AND-RESPONSIVE.md](../flutter/LAYOUT-AND-RESPONSIVE.md#safearea-and-mediaquery)); the full list is in [REVIEW.md](REVIEW.md#where-a-rule-differs-from-flutters-docs).
8. **A design review never edits the app.** It writes only under `docs/improvements/design/`, prints findings without locations or counts, waits for the developer to pick, and writes plans a session with zero context can execute [improve-design] ([REVIEW.md](REVIEW.md)). Reviewing a pull request's diff is [../../architecture/code-review/SKILL.md](../../architecture/code-review/SKILL.md); cleaning up agent-written code is [../../anti-ai-slop/anti-slop-code/SKILL.md](../../anti-ai-slop/anti-slop-code/SKILL.md); a visual-design review ranked P0 to P3 is [../../anti-ai-slop/anti-slop-ui/SKILL.md](../../anti-ai-slop/anti-slop-ui/SKILL.md); its "Every data view has its states" is the same idea rule 4 applies to images.

## Prove it

A run of [REVIEW.md](REVIEW.md) over the app, against [REVIEW-CATALOG.md](REVIEW-CATALOG.md), returns no finding for the rules the team chose to adopt; on a device, scrolling a form closes the keyboard, the last field's action key submits, a modal closes without the keyboard coming back, the last list item clears the system bar, images keep their box and fade in, and every number, date and phone number reads in the user's format; each rule that differs from [../flutter/SKILL.md](../flutter/SKILL.md) was decided with both sides shown, and the app still passes that skill's checks at the largest OS font; and every file's own Prove it checks pass for the parts you touched.
