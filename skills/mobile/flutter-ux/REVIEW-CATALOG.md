# Design review catalog

The 42 rules the [REVIEW.md](REVIEW.md) mode scans a Flutter app against, in catalog order. Each rule: title, **Why** (shown to the developer as-is), **Flag** (what counts), **Hunt** (where to start), **Fix** (one line; the full fix is in the named topic file), and its FlutterPro article. Rules from [improve-design]; articles by Kamran Bekirov. A **Differs** line points to [where a rule differs from Flutter's docs](REVIEW.md#where-a-rule-differs-from-flutters-docs); show both sides in the plan.

**Contents:** [Forms, keyboard and focus](#forms-keyboard-and-focus) · [Navigation and sheets](#navigation-and-sheets) · [Scrolling and layout](#scrolling-and-layout) · [Images and typography](#images-and-typography) · [Motion and feedback](#motion-and-feedback) · [Notifications](#notifications) · [App lifecycle](#app-lifecycle) · [Web and platform](#web-and-platform) · [Formatting](#formatting) · [Prove it](#prove-it)

## Forms, keyboard and focus

**1. Dismiss the keyboard when the user scrolls.** Why: the user finishes typing and scrolls to see the rest, but the keyboard stays covering half the screen. Scrolling means they're done with the field, so close it for them. Flag: a scrollable with a text field inside that doesn't set `keyboardDismissBehavior` to `onDrag`; chat screens stay `manual`, since the user scrolls while still typing. Hunt: `TextField|TextFormField|CupertinoTextField`, then the enclosing `ListView|SingleChildScrollView|CustomScrollView|GridView`. Fix: `keyboardDismissBehavior: ScrollViewKeyboardDismissBehavior.onDrag` on that scrollable. File: [KEYBOARD-AND-FOCUS.md](KEYBOARD-AND-FOCUS.md). [FlutterPro](https://flutterpro.design/details/dismiss-keyboard-on-scroll)

**2. Autofocus the field when the page has only one.** Why: a page that exists to collect one input (OTP, phone number, change email) makes the user tap the field before they can type. Focus it on open: the keyboard is up, they type and move on. Flag: a page whose only interactive element is one text field without `autofocus: true`; pages with other choices next to the field (login with social buttons) are correct without it. Hunt: `Pinput|pin_code|otp|Otp|OTP|smsCode|verification`, then files like `change_email|change_phone|edit_name|forgot_password`. Fix: `autofocus: true` on that field. File: [KEYBOARD-AND-FOCUS.md](KEYBOARD-AND-FOCUS.md). [FlutterPro](https://flutterpro.design/details/autofocus-single-field)

**3. Unfocus the text field before opening a modal.** Why: opening a modal while a text field is focused brings the keyboard back when the modal closes, even though the user was done typing. Flag: a page with a focusable field and any modal opener (picker, dropdown, sheet, dialog) that doesn't call `FocusManager.instance.primaryFocus?.unfocus()` first; `FocusScope.of(context).unfocus()` is the wrong tool, "it finds the nearest scope, not the actually focused field". Hunt: `showModalBottomSheet|showDialog|showDatePicker|showCupertinoModalPopup` in files that also have `TextField|TextFormField`. Fix: call `FocusManager.instance.primaryFocus?.unfocus()` before opening. File: [KEYBOARD-AND-FOCUS.md](KEYBOARD-AND-FOCUS.md). [FlutterPro](https://flutterpro.design/details/unfocus-before-modal)

**4. Give every text field the right keyboard action.** Why: users should fill a form and submit it with the keyboard's action key alone: it moves them to the next field and, on the last one, submits. Flag: two or more single-line fields without `textInputAction` (`.next` on the others, `.done` or `.send`/`.go`/`.search` on the last, with the submit in `onFieldSubmitted`); multiline fields are exempt. Hunt: files with two or more `TextField|TextFormField`, then `textInputAction`. Fix: set `textInputAction` per field and submit from the last one's `onFieldSubmitted`. File: [KEYBOARD-AND-FOCUS.md](KEYBOARD-AND-FOCUS.md). [FlutterPro](https://flutterpro.design/details/text-input-action)

**5. Keep the dial code from doubling in phone fields.** Why: the phone field shows the dial code as a static prefix, but paste and autofill insert the full number with the code again, so the user fixes it by hand. Flag: a phone field with a separate dial code (`prefixText`, a prefix widget, a country picker) and no `inputFormatters` entry stripping it from pasted or autofilled input. Hunt: `TextInputType.phone|AutofillHints.telephoneNumber|prefixText`. Fix: an input formatter that strips the dial code when the text grows by more than one character. File: [FORMS-AND-INPUT.md](FORMS-AND-INPUT.md). [FlutterPro](https://flutterpro.design/details/autofill-dial-code)

**6. Don't let amount fields go over the limit.** Why: letting the user type past an amount limit and then showing an error is needless friction; a field that never accepts more than the limit is better. Flag: an amount field with a hard maximum (balance, limit, order total) that accepts more and complains afterwards (field error, snackbar, dialog, rejected submit). Hunt: `numberWithOptions|TextInputType.number`, then `insufficient|exceeds|too (much|high)|maxAmount|balance`. Fix: an input formatter that blocks the edit past the maximum. File: [FORMS-AND-INPUT.md](FORMS-AND-INPUT.md). [FlutterPro](https://flutterpro.design/details/max-amount-formatter)

## Navigation and sheets

**7. Scroll to top when the current bottom nav item is tapped again.** Why: tapping the bottom nav item you're already on should scroll that page to the top; native app users have the muscle memory and expect it. Flag: a bottom nav bar whose tap handler (or the state behind it) has no reselect branch. Hunt: `BottomNavigationBar|NavigationBar|CupertinoTabBar`, then a same-index check like `index == currentIndex`. Fix: on a same-index tap, animate that tab's `ScrollController` to 0. File: [NAVIGATION-AND-SHEETS.md](NAVIGATION-AND-SHEETS.md). [FlutterPro](https://flutterpro.design/details/bottom-nav-reselect)

**8. Don't use mobile page transitions on web and desktop.** Why: web and desktop are click and open; mobile slide and zoom transitions look cheap there, so pages should switch with no transition. Flag: a `web/`, `macos/`, `windows/` or `linux/` folder and nothing in `pageTransitionsTheme` or the router that disables transitions there. Hunt: `pageTransitionsTheme|PageTransitionsBuilder|pageBuilder`, then `kIsWeb` or desktop builders. Fix: a no-transition builder for web and desktop. Differs: see [Android transitions](REVIEW.md#where-a-rule-differs-from-flutters-docs). File: [NAVIGATION-AND-SHEETS.md](NAVIGATION-AND-SHEETS.md). [FlutterPro](https://flutterpro.design/details/web-page-transitions)

**9. Make bottom sheets smooth and draggable.** Why: Material's `showModalBottomSheet` opens and closes with a mechanical, soulless motion; bottom sheets should respond to drags smoothly. Flag: small non-scrolling sheets opened with `showModalBottomSheet`; full-screen scrollable sheets belong to rule 10. Hunt: `showModalBottomSheet`. Fix: the spring sheet (`showSpringBottomSheet`, same call shape) that keeps a fling's speed and settles like a spring. File: [NAVIGATION-AND-SHEETS.md](NAVIGATION-AND-SHEETS.md). [FlutterPro](https://flutterpro.design/details/smooth-draggable-bottom-sheets)

**10. Give full-screen modals the modern sheet look.** Why: full-screen modals from the bottom either use the iOS 13 sheet style, which looks dated now, or just slide up mechanically. Make them smooth, closing with a pull down from the top. Flag: a full-screen bottom modal via `CupertinoSheetRoute` or `showModalBottomSheet(isScrollControlled: true)`. Hunt: `CupertinoSheetRoute|isScrollControlled`. Fix: the adaptive sheet route (glass sheet on iOS, plain sheet on Android) with a close X at the top left. Differs: see [full-screen sheets](REVIEW.md#where-a-rule-differs-from-flutters-docs). File: [NAVIGATION-AND-SHEETS.md](NAVIGATION-AND-SHEETS.md). [FlutterPro](https://flutterpro.design/details/adaptive-sheet-route)

## Scrolling and layout

**11. Make horizontal lists feel scrollable.** Why: a horizontal list doesn't always signal that it scrolls, especially when the visible items just fit. Fading the edge hints there's more. Flag: a horizontal scrollable whose end edge doesn't fade. Hunt: `Axis.horizontal|scrollDirection: Axis.horizontal`, then `ShaderMask|LinearGradient` around it. Fix: a `ShaderMask` gradient fading the end edge. Differs: see [edge fades cost](REVIEW.md#where-a-rule-differs-from-flutters-docs). File: [SCROLLING-AND-LAYOUT.md](SCROLLING-AND-LAYOUT.md). [FlutterPro](https://flutterpro.design/details/shader-mask)

**12. Scroll the tapped tab fully into view.** Why: when the user taps a tab that's only half visible, it should scroll fully into view. Flag: a custom horizontal tab row (chips, filters, categories) whose selection doesn't scroll it into view; Material's `TabBar` already does. Hunt: a horizontal `ListView|SingleChildScrollView` with tappable items tracking a selected index, then `Scrollable.ensureVisible`. Fix: `Scrollable.ensureVisible` on the tapped item's context when it's selected. File: [SCROLLING-AND-LAYOUT.md](SCROLLING-AND-LAYOUT.md). [FlutterPro](https://flutterpro.design/details/tab-visibility)

**13. Make the whole GestureDetector area tappable.** Why: by default `GestureDetector` only takes taps on what its child paints, so padding and the gaps between an icon and a text do nothing; the user taps the row and misses. Flag: a `GestureDetector` whose `behavior` isn't `opaque` or `translucent` and whose child has unpainted areas (padding, `Row`/`Column` gaps, a `Container` without a color). Hunt: `GestureDetector`, then `behavior:`. Fix: `behavior: HitTestBehavior.opaque`. File: [SCROLLING-AND-LAYOUT.md](SCROLLING-AND-LAYOUT.md). [FlutterPro](https://flutterpro.design/details/gesture-detector-hit-area)

**14. Keep statusbar tap scrolling to top on iOS.** Why: tapping the status bar scrolls the page to the top, native to iOS; it works out of the box, but a custom `ScrollController` silently breaks it. Flag: a vertical scrollable with its own `ScrollController` in a `Scaffold` (or `CupertinoPageScaffold`) with no `PrimaryScrollController` above it providing that controller. Hunt: `ScrollController(`. Fix: wrap it in `PrimaryScrollController(controller: <that controller>, ...)`. File: [SCROLLING-AND-LAYOUT.md](SCROLLING-AND-LAYOUT.md). [FlutterPro](https://flutterpro.design/details/statusbar-tap-scroll)

**15. Let horizontal lists reach the screen edges.** Why: when the page's scrollable has horizontal padding, horizontal lists inside get clipped at the padding line instead of sliding past the edges. Flag: a horizontal list nested in a page scrollable with horizontal padding. Hunt: `Axis.horizontal|scrollDirection: Axis.horizontal`, then the enclosing padding. Fix: take the list out of the page padding and give the list its own padding. File: [SCROLLING-AND-LAYOUT.md](SCROLLING-AND-LAYOUT.md). [FlutterPro](https://flutterpro.design/details/horizontal-list-padding)

**16. Reserve space for images before they load.** Why: an image has no size until its bytes arrive, so it snaps to its real height and pushes everything below it down. Size its box first so the layout doesn't jump. Flag: a network image with no size decided before load (no `AspectRatio`, no width and height, no height-bounding parent); "`fit:` doesn't count", and width alone doesn't either. Hunt: `Image.network|CachedNetworkImage|NetworkImage`. Fix: an `AspectRatio` or explicit width and height around the image. File: [SCROLLING-AND-LAYOUT.md](SCROLLING-AND-LAYOUT.md). [FlutterPro](https://flutterpro.design/details/reserve-image-space)

**17. Don't let the system navigation bar cover the bottom of scrollable lists.** Why: the last item of a scrollable list gets hidden under the system navigation bar. Leave space as tall as the bar at the end of the list so the last item has breathing room. Flag: a vertical scrollable running to the bottom of the screen with no end space as tall as the system bar; `SafeArea` around it and a fixed padding like 24 don't count. Hunt: `ListView|SingleChildScrollView|CustomScrollView|GridView|NestedScrollView`, then `viewPaddingOf|viewPadding.bottom|BottomPadding`, and `SafeArea` for the wrong fix. Fix: bottom padding from `MediaQuery.viewPaddingOf(context).bottom` with a minimum (the `BottomPadding` widget). Differs: see [SafeArea on scrollables](REVIEW.md#where-a-rule-differs-from-flutters-docs). File: [SCROLLING-AND-LAYOUT.md](SCROLLING-AND-LAYOUT.md). [FlutterPro](https://flutterpro.design/details/safe-area-replacement)

**18. Fade scrolling content under the status bar.** Why: on pages with no app bar, scrolling content runs behind the status bar and collides with the clock and battery. A progressive fade at the top dissolves it as it slides under. Flag: a `Scaffold` without `appBar:` whose scrolling body has no top fade. Hunt: `Scaffold(` without `appBar:`, then `ShaderMask|ProgressiveFade`. Fix: a top-down `ShaderMask` gradient around the body. Differs: see [edge fades cost](REVIEW.md#where-a-rule-differs-from-flutters-docs). File: [SCROLLING-AND-LAYOUT.md](SCROLLING-AND-LAYOUT.md). [FlutterPro](https://flutterpro.design/details/progressive-fade)

**19. Show scrollbars on vertical scrollables.** Why: a scrollbar shows the user where they are in the list and how much is left. Flag: a vertical scrollable neither wrapped in `Scrollbar` nor covered by an app-wide `scrollBehavior` whose `buildScrollbar` wraps in `Scrollbar` (overrides exist for other reasons too). Hunt: `scrollBehavior|MaterialScrollBehavior`, then `ListView|SingleChildScrollView|CustomScrollView|GridView`. Fix: wrap in `Scrollbar` on mobile, or an app-wide scroll behavior that does. Differs: see [scrollbars](REVIEW.md#where-a-rule-differs-from-flutters-docs). File: [SCROLLING-AND-LAYOUT.md](SCROLLING-AND-LAYOUT.md). [FlutterPro](https://flutterpro.design/details/scrollbars)

**20. Adapt layouts at the user's text scale.** [Owner's rule, via flutter ACCESSIBILITY]: never cap text scaling app-wide; restructure a row when large text breaks it, and limit clamping to one region that truly cannot grow. Flag: an app-wide cap, or content that overflows at the largest OS font size. Hunt: `textScaler|textScaleFactor`, then the layout that breaks. Fix: remove the app-wide cap and adapt the structure, following [Text scale cap](SCROLLING-AND-LAYOUT.md#text-scale-cap). [FlutterPro](https://flutterpro.design/details/text-scale-factor) instead prescribes an app-wide 1.1 cap; that source view is retained in the topic, but the owner rule wins. Differs: [REVIEW.md](REVIEW.md#where-a-rule-differs-from-flutters-docs).

## Images and typography

**21. Match text selection to your app's colors.** Why: `MaterialApp` applies default tinted colors to text selection in inputs; match them to your brand instead. Flag: text the user can select or type into, and no `textSelectionTheme` in the theme. Hunt: `textSelectionTheme`; if absent, `TextField|TextFormField|CupertinoTextField|EditableText|SelectableText|SelectionArea|SelectableRegion`. Fix: set `textSelectionTheme` (cursor, selection, handles) to brand colors. File: [IMAGES-AND-TYPOGRAPHY.md](https://github.com/Quegenx/agent-skills/blob/main/skills/mobile/flutter-ui/IMAGES-AND-TYPOGRAPHY.md). [FlutterPro](https://flutterpro.design/details/selection-color)

**22. Load network images smoothly.** Why: images load with no transition, no placeholder and no failure state; they just pop in. Show a plain grey box until each picture is ready and fade it in; if it fails, show a subtle broken image icon, never a technical message. Flag: a network image missing any of transition, loading placeholder or failure state; `FadeInImage` or `image_fade` alone isn't enough; assets are out of scope. Hunt: `Image.network|NetworkImage|CachedNetworkImage|ExtendedImage|FadeInImage|image_fade`. Fix: grey placeholder, fade in, subtle broken-image icon. File: [IMAGES-AND-TYPOGRAPHY.md](https://github.com/Quegenx/agent-skills/blob/main/skills/mobile/flutter-ui/IMAGES-AND-TYPOGRAPHY.md). [FlutterPro](https://flutterpro.design/details/smooth-image-loading)

**23. Preload images and icons so they don't pop in.** Why: Flutter loads and decodes images and icons when a widget first asks for them, so they paint a few frames late. Precache them during splash so they're ready. Flag: asset icons and images (`SvgPicture`, `Image.asset`, `AssetImage`) without preloading the first-screen assets; other assets may load in the background ([canonical boundary](https://github.com/Quegenx/agent-skills/blob/main/skills/mobile/flutter-ui/IMAGES-AND-TYPOGRAPHY.md#preload-icons-during-the-splash)). Hunt: `SvgPicture|Image.asset|AssetImage|Assets\.`, then `precacheImage|svg.cache`. Fix: precache during splash (`precacheImage`, `svg.cache`). File: [IMAGES-AND-TYPOGRAPHY.md](https://github.com/Quegenx/agent-skills/blob/main/skills/mobile/flutter-ui/IMAGES-AND-TYPOGRAPHY.md). [FlutterPro](https://flutterpro.design/details/precache-icons)

**24. Preload Google Fonts so text doesn't swap fonts.** Why: `google_fonts` downloads fonts on first use, so on a fresh install text shows in the default font for a split second before it swaps. Preload during splash and text is right from frame one. Flag: `google_fonts` used and nothing awaits `GoogleFonts.pendingFonts` at startup with the exact weights and styles; "a bare `GoogleFonts.pendingFonts([GoogleFonts.inter()])` only loads weight 400 normal". Hunt: `google_fonts` in pubspec (none means the rule doesn't apply), then `pendingFonts`. Fix: await `GoogleFonts.pendingFonts` for the exact weights and styles needed immediately; load the rest in the background ([canonical boundary](https://github.com/Quegenx/agent-skills/blob/main/skills/mobile/flutter-ui/IMAGES-AND-TYPOGRAPHY.md#preload-google-fonts)). File: [IMAGES-AND-TYPOGRAPHY.md](https://github.com/Quegenx/agent-skills/blob/main/skills/mobile/flutter-ui/IMAGES-AND-TYPOGRAPHY.md). [FlutterPro](https://flutterpro.design/details/google-fonts-glitch)

**25. Use tabular figures for changing numbers.** Why: digits have different widths in most fonts, so a timer or counter jumps as it changes. Tabular figures make every digit the same width, so numbers stay still and line up. Flag: a changing number (timer, counter, price) or aligned one (table, totals) without `FontFeature.tabularFigures()`; numbers in a sentence don't need it. Hunt: `tabularFigures`, then `Timer|Stopwatch|Duration|countdown|price|total|amount` near `Text(`. Fix: `fontFeatures: [FontFeature.tabularFigures()]` on that text style. File: [IMAGES-AND-TYPOGRAPHY.md](https://github.com/Quegenx/agent-skills/blob/main/skills/mobile/flutter-ui/IMAGES-AND-TYPOGRAPHY.md). [FlutterPro](https://flutterpro.design/details/tabular-figures)

## Motion and feedback

**26. Teach users swiping an item right and left for actions.** Why: users without the muscle memory to swipe never find the actions behind list items. Open and close them programmatically the first time the page opens to teach the gesture. Flag: rows with swipe actions and nothing ever shows them. Hunt: `Slidable|Dismissible|SlidableController`; a controller paired with a one-time flag means the hint exists. Fix: a `SlidableController` hint shown once, behind a saved flag. File: [MOTION-AND-FEEDBACK.md](MOTION-AND-FEEDBACK.md). [FlutterPro](https://flutterpro.design/details/flutter-slidable-controller)

**27. Add haptic feedback to key moments.** Why: the app feels flat when taps and results happen in silence. A subtle haptic on a tab switch, a successful submit or an error makes it feel responsive in the hand. Flag: one key moment without a haptic: a tab tapped, a successful submit (login, register, payment), an error snackbar, a toggle, a picker scrolled; "The app using haptics somewhere doesn't count". Hunt: `HapticFeedback|haptic_feedback|Haptics\.|vibrate`, then `BottomNavigationBar|NavigationBar|TabBar`, `SnackBar|showSnackBar`, `Switch|Checkbox|onLongPress`. Fix: a subtle haptic on each of those moments (the `HapticsHelper` wrapper). File: [MOTION-AND-FEEDBACK.md](MOTION-AND-FEEDBACK.md). [FlutterPro](https://flutterpro.design/details/haptic-feedback)

**28. Strip Material tap effects from custom designs.** Why: Material widgets ripple and glow on tap by default, and in an app with its own design language those effects clash with it. Flag: decide the app first: a Material design app (Material 3 or Expressive, mostly Material widgets) needs its ripples and the rule doesn't apply. A custom-design app that still uses some Material widgets must strip them at both levels: global (`splashFactory: NoSplash.splashFactory`, transparent `splashColor`, `highlightColor`, `hoverColor`, `focusColor`) and each used widget's component theme `overlayColor`, "since M3 widgets draw their press overlay from their own component theme". Hunt: `NoSplash|splashColor|highlightColor|hoverColor|focusColor` in `ThemeData`, then `overlayColor` in the used widgets' themes. Fix: both levels, for the widgets the app uses. The catalog doesn't ask for a replacement pressed state; the web counterpart in [app-ui CHECKS.md](https://github.com/Quegenx/agent-skills/blob/main/skills/web-ui/app-ui/CHECKS.md) flags a removed tap highlight with no pressed style. File: [MOTION-AND-FEEDBACK.md](MOTION-AND-FEEDBACK.md). [FlutterPro](https://flutterpro.design/details/strip-material-tap-effects)

## Notifications

**29. Preserve the intended local notification time across timezone changes.** Why: the user's selected local reminder time can differ after travel or clock changes. Flag: scheduled notifications whose actual platform/schedule behavior fails that intended local time. Hunt: `zonedSchedule|flutter_local_notifications|TZDateTime`, the recurrence components and zone handling. Fix: follow the [scheduling contract and source recipe](NOTIFICATIONS-AND-PERMISSIONS.md#reschedule-on-timezone-or-clock-change). [FlutterPro](https://flutterpro.design/details/timezone-change) saves the timezone name and UTC offset, compares on open/resume and cancels/reschedules on change; the topic's P2 correction explains why not every schedule is a UTC instant that loses local-time intent. Do not flag another correct recurrence solely for omitting that particular recipe.

## App lifecycle

**30. Show what's new after an update.** Why: after an update nothing tells users what's new, so the bug you fixed and the feature they asked for go unnoticed. Show them as a list on first open after an update, and the user who asked knows you listened. Flag: no view that comes up on its own the first time a new version opens; a changelog page in settings or a profile doesn't count. Hunt: `changelog|whats_new|whatsNew|release_notes|last_seen_version|version_history`; nothing found means missing. Fix: compare the last seen version with the current one on open and show the unseen entries once. File: [APP-LIFECYCLE.md](APP-LIFECYCLE.md). [FlutterPro](https://flutterpro.design/details/in-app-changelog)

**31. Show the app version in settings.** Why: when a user reports a bug, the first question is which version they're on, and the app has no place to answer it. Flag: nothing displays the version with its build number, plus the patch number if the app uses Shorebird. Hunt: `PackageInfo|package_info_plus|buildNumber`; with `shorebird` in pubspec, also `readCurrentPatch`. Fix: show version, build and (with Shorebird) patch number in settings. File: [APP-LIFECYCLE.md](APP-LIFECYCLE.md). [FlutterPro](https://flutterpro.design/details/show-app-version)

**32. Show a friendly view when a widget breaks.** Why: when a widget fails to build, users see an empty grey box in release. Show a friendly "Something went wrong" in the app's own colors instead. Flag: no custom `ErrorWidget.builder`. Hunt: `ErrorWidget.builder`. Fix: set `ErrorWidget.builder` to a friendly view in the app's colors. File: [APP-LIFECYCLE.md](APP-LIFECYCLE.md). [FlutterPro](https://flutterpro.design/details/friendly-error-view)

**33. Report real screen names to analytics.** Why: analytics sees a Flutter app as one native view, so every page reports as `FlutterViewController` and you can't tell which screens users spend time on. Flag: an analytics navigator observer, plus one missing piece: the SDK's native automatic screen reporting still on in `ios/` and `android/` (each SDK has its own switch; some report by session capture instead), or routes pushed without names (plain `Navigator.push` with no `RouteSettings` name). No observer means the rule doesn't apply. Hunt: `AnalyticsObserver|navigatorObservers|observers:`, then the native switch, then `Navigator.of|MaterialPageRoute` without `RouteSettings(name:`. Fix: turn off native automatic reporting and name every pushed route. Differs: see [named routes](REVIEW.md#where-a-rule-differs-from-flutters-docs). File: [APP-LIFECYCLE.md](APP-LIFECYCLE.md). [FlutterPro](https://flutterpro.design/details/analytics-screen-names)

## Web and platform

**34. Show loading progress while Flutter web boots.** Why: Flutter web takes a few seconds to boot, and users stare at a blank white page wondering if the site is broken. Show a splash or progress bar so they know the app is coming. Flag: `web/index.html` whose `<body>` has only script tags (or `flutter_bootstrap.js` alone). Hunt: `web/index.html` (none means the rule doesn't apply), then its `<body>`. Fix: splash or progress markup in `<body>`, which Flutter replaces when it mounts. File: [WEB-SHELL.md](WEB-SHELL.md). [FlutterPro](https://flutterpro.design/details/flutter-web-loading-progress)

**35. Give Flutter web links a preview card.** Why: shared in WhatsApp, Slack or X, the app's link shows as a bare URL; it should show a card with a title, description and image. Flag: `web/index.html` with no Open Graph tags; `og:image` must be absolute; X can fall back from `twitter:image` to `og:image` ([documented fallback](WEB-SHELL.md#link-previews-with-open-graph)). The old catalog required both image tags on the claim that X reads only its own tags. Hunt: `og:title|og:image|twitter:card` in `web/index.html`. Fix: Open Graph and Twitter tags with title, description and an absolute image URL. File: [WEB-SHELL.md](WEB-SHELL.md). [FlutterPro](https://flutterpro.design/details/flutter-web-og-image)

**36. Update the browser tab title per page.** Why: the tab title shows in the browser tab, history and bookmarks, and when it's the same on every page, a user with several tabs open can't tell them apart. Flag: a `web/` folder and nothing updates the title per page; a static app title or `onGenerateTitle` ("it only reruns on app rebuild, not navigation") doesn't count. Hunt: `Title(`. Fix: a `Title` widget per page, or a wrapper in the app's `builder` that listens to the router and rebuilds a `Title`. File: [WEB-SHELL.md](WEB-SHELL.md). [FlutterPro](https://flutterpro.design/details/browser-tab-title)

**37. Open social media links in their apps.** Why: a social media link should open the app directly if it's installed, not the browser. Flag: a social link launched without `mode: LaunchMode.externalApplication`, or through a custom scheme like `instagram://`, which fails when the app isn't installed. Hunt: `instagram|twitter|x\.com|facebook|whatsapp|wa\.me|tiktok|linkedin|youtube` near `launchUrl`. Fix: `launchUrl` with the https URL and `mode: LaunchMode.externalApplication`. File: [DEVICE-FEATURES.md](DEVICE-FEATURES.md#open-social-media-apps). [FlutterPro](https://flutterpro.design/details/launch-social-media-apps)

**38. Don't show the iOS date picker on Android.** Why: `CupertinoDatePicker` is iOS-native; Android users don't expect a scroll-wheel picker, and an iOS widget on Android reads as cheap. Flag: a `CupertinoDatePicker` with no platform branch. Hunt: `CupertinoDatePicker`, then `defaultTargetPlatform|Platform.isIOS`. Fix: Cupertino picker on iOS, Material `showDatePicker` on Android. Differs: see [platform branches](REVIEW.md#where-a-rule-differs-from-flutters-docs). File: [NAVIGATION-AND-SHEETS.md](NAVIGATION-AND-SHEETS.md#date-picker-that-matches-the-platform). [FlutterPro](https://flutterpro.design/details/adaptive-date-picker)

## Formatting

**39. Never show "null" on screen.** Why: when a string comes back `null` or empty from the API and is displayed directly, the user sees the word "null" or a blank spot. Show "-" or "N/A" instead. Flag: display text from API values with no shared guard covering `null`, `"null"` as a serialized string, and empty; scattered `?? '-'` only covers `null`. Hunt: `orPlaceholder|isUsable|!= 'null'`; nothing found means missing. Fix: one shared helper (an `orPlaceholder()` extension) used for display text. File: [FORMATTING.md](FORMATTING.md). [FlutterPro](https://flutterpro.design/details/never-show-null)

**40. Format numbers for user's locale.** Why: a raw `1234567` is hard to read; users expect `1,234,567` in the US and `1.234.567` in Germany, for every count, price and big number. Flag: amounts, counts or prices rendered via `.toString()` or interpolation instead of `NumberFormat` from `intl`. Hunt: `NumberFormat|decimalPattern|simpleCurrency|compact\(`, then `\$\{.*(price|amount|total|count|balance)|\.toStringAsFixed|\.toString\(\)` inside `Text(`. Fix: a shared `NumberFormat` helper for display. File: [FORMATTING.md](FORMATTING.md). [FlutterPro](https://flutterpro.design/details/format-numbers-for-humans)

**41. Format dates for user's locale.** Why: `2016-06-24 14:44:00.000` is what `DateTime` prints, and no user should read a date like that; show `24 July 2016, 14:44` in the user's language. Flag: a date shown without `DateFormat`: `.toString()`, an interpolated `DateTime`, or `'$day/$month/$year'`. Hunt: `DateFormat`, then `DateTime` near `Text(` and `.day|.month|.year|.hour|.minute` in interpolations. Fix: `DateFormat` through a shared `DateTime` extension. File: [FORMATTING.md](FORMATTING.md). [FlutterPro](https://flutterpro.design/details/format-date-times)

**42. Format phone numbers.** Why: a phone number shown or typed as one long run of digits is hard to read and easy to mistype; format it everywhere the user sees one, including while typing. Flag: a raw phone value in a `Text(`, or a phone field with no formatting `inputFormatters`. Hunt: `phone|phoneNumber|msisdn`, then `MaskTextInputFormatter|inputFormatters|maskPhoneNumber|phone_numbers_parser`. Fix: format on display and with an input formatter while typing. File: [FORMATTING.md](FORMATTING.md). [FlutterPro](https://flutterpro.design/details/format-phone-numbers)

Rules 2 and 6 have web counterparts that differ, for a different stack: app-ui's checker drops page autofocus unless "typing is the one thing to do and the device has a keyboard", and its steppers "clamp on blur" instead of blocking the edit ([app-ui reference/scripts/design-system/check-system.mjs](https://github.com/Quegenx/agent-skills/blob/main/skills/web-ui/app-ui/reference/scripts/design-system/check-system.mjs), [app-ui CONTROLS.md](https://github.com/Quegenx/agent-skills/blob/main/skills/web-ui/app-ui/CONTROLS.md)).
