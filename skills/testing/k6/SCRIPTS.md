# Writing k6 scripts

A k6 script is a JavaScript module: `export const options` sets the load, the default export (or a scenario's `exec` function) is one iteration, and only `thresholds` decide whether the run passes. Three traps recur: code that throws before any `check()` runs (so thresholds pass on zero samples), mistaking per-VU module state for shared state, and options or imports copied from an older k6. Load shapes, executors and thresholds are in [LOAD-AND-THRESHOLDS.md](LOAD-AND-THRESHOLDS.md); browser scripts in [BROWSER.md](BROWSER.md).

## Authoring workflow

The following filenames belong to the upstream Grafana skills bundle; this folder does not ship those JavaScript examples. Read the relevant local topic below, or fetch and fully read the matching upstream example before adapting it. Do not report an absent example as a local template. [existing SCRIPTS.md]

Read the matching source, adapt it, save it, validate it, review it. Skip the todo list.

| Request | Upstream example filename, not shipped here |
|---|---|
| HTTP REST, auth, batch | `http.js` |
| `parseHTML` and `SharedArray` | `html.js` |
| WebSocket | `websocket.js` |
| gRPC | `grpc.js` |
| Browser automation, load or perf | `browser.js` |
| Browser plus functional, `expect()`, k6-testing | `functional.js` |
| Custom metrics, execution module, `handleSummary`, `per-vu-iterations` | `metrics.js` |

| Cloud run, `--local-execution`, `cloud` options | `cloud.js` |

- **When several rows match:** "functional test", "assert", "verify" or "expect" means `functional.js`, even for a browser test; a browser load or perf test without correctness emphasis means `browser.js`. If selectors are unknown and must be found on the live site, use the exploration loop in [BROWSER.md](BROWSER.md).
- **Adapt to complete, runnable code:** no `{ ... }`, `// TODO` or stubs. Match the request, don't over-build: no unrequested custom tags, extra `sleep()`, extra endpoints or `options`. Multi-scenario scripts (browser plus HTTP, cloud) use named `scenarios` with `exec` pointing at separate exported functions.
- **TypeScript:** the grafana/k6 example `examples/enhanced/script.ts` imports `./user.ts`; its compatibility and loader requirements were not checked against current docs, so treat it as an upstream example only. GitHub Actions examples are excluded. [existing SCRIPTS.md; owner GitHub lifecycle exclusion]
- **Look up docs only** when the example lacks an API or option, or you are unsure of a signature. Do not use unpkg, `@types/k6` or any npm type definition URLs.
- **Save to disk:** line 1 is a generated-by comment with the UTC timestamp from `date -u +%Y-%m-%dT%H:%M:%SZ` (for example `// Generated by grafana-k6 on 2026-03-25T22:02:20.203Z`); path `k6/scripts/<descriptive-name>.js`, lowercase kebab-case (`mkdir -p k6/scripts`). The file on disk is the deliverable; never leave the script only in chat.
- **Validate, first matching row wins:**

| Script | Command |
|---|---|
| Imports `k6/browser` | `k6 run k6/scripts/<name>.js` |
| Any `ramping-vus` or `*-arrival-rate` scenario | `k6 inspect k6/scripts/<name>.js` (a full run would execute the whole load profile) |
| Other named `executor:` blocks (short) | `k6 run` |
| Everything else (HTTP, WS, gRPC) | `k6 run --once k6/scripts/<name>.js` on k6 v2.3+; `k6 run --vus 1 --iterations 1 k6/scripts/<name>.js` on older k6 |

  The options reference says to use `--once` instead of `--vus 1 --iterations 1`; it keeps the scenario's function and browser options and accepts at most one scenario ([options reference](https://grafana.com/docs/k6/latest/using-k6/k6-options/reference/), [VERSIONS.md](VERSIONS.md)).

- **Passing:** functional and browser scripts need exit 0 and no failed checks or `expect()` errors. Load tests pass on exit 0; a pure threshold breach under load (exit 99) is acceptable. Retry fixes up to 3 times, then show the error and ask (unattended: deliver the best attempt and report).
- **Present** the full script with its path, the validation output, best-practice notes and a run command. Run it only if the user confirms. Example commands: `k6 run --vus 10 --duration 30s k6/scripts/api-load-test.js`, `k6 run k6/scripts/browser-test.js`, `k6 cloud run k6/scripts/cloud-test.js`, `k6 cloud run --local-execution k6/scripts/hybrid-test.js`, `k6 run k6/scripts/faker-test.js` (the `k6/x/faker` import provisions the extension, see [xk6 extensions](#xk6-extensions)), `K6_BROWSER_HEADLESS=true k6 run k6/scripts/browser-test.js`.

## Rules for every script

- **`export const options`** with realistic VUs and duration.
- **Thresholds on every load test:** without them the run cannot fail in CI. Minimum `http_req_duration` and `http_req_failed` (or the protocol's equivalent). Single-iteration `expect()`-only functional scripts may skip them.
- **Think time in closed-model tests:** include `sleep()` in VU-based load tests. Open-model executors (`constant-arrival-rate`, `ramping-arrival-rate`) already pace iterations, so `sleep()` there is usually unnecessary. Browser scripts use `page.waitForTimeout()`. Single-iteration functional tests and one-shot connectivity scripts can skip it. In event-driven WebSocket scripts put `sleep()` in the `close` handler.
- **Assert every response.** Silent failures are worse than loud ones. Browser: `expect()` from k6-testing. HTTP, gRPC, WS: `check()` for metric-tracked assertions, or `expect()` for functional tests.
- **Clean up:** browser interactions in `try/finally` with `page.close()` in `finally`; gRPC calls in `try/finally` with `client.close()` in `finally`; WebSocket `JSON.parse` of incoming messages in `try/catch`. Close file handles and connections.
- **Module state belongs to each VU.** Each VU has its own JavaScript environment; mutable module globals are not shared between VUs. Use `SharedArray` for the documented read-only shared-data case. The source incorrectly said module-scope state was shared. Its ban on top-level `let`/`var` remains an authoring preference, not a VU-isolation requirement. [k6 global variables](https://grafana.com/docs/k6/latest/examples/use-global-variables/)
- **No deprecated imports:** use `k6/websockets`; `k6/ws` and `k6/experimental/websockets` are both deprecated. `k6/experimental/redis` was removed in v2.0.0: import `k6/x/redis` ([k6 release notes v2.0.0](https://github.com/grafana/k6/blob/master/release%20notes/v2.0.0.md)).
- **No hardcoded secrets:** read them from `__ENV`, or for credentials from `k6/secrets`, whose values k6 redacts from its logs while `__ENV` values are not redacted ([Secrets](#secrets)). Load test data files through `SharedArray`.
- **Track SLO metrics:** per-endpoint latency (`Trend`), error `Rate`, domain counters, plus a `handleSummary` that surfaces p95/p99, throughput (req/s) and error rate.
- **Hybrid protocol plus browser load tests:** wrap the browser flow in `try/catch` and record failures to a custom error metric instead of letting `expect()` throw, so one flaky browser iteration does not abort a long protocol run. (The website suite instead records an `iteration_completed` Rate and re-throws; see [WEBSITE-LOAD-AND-REPORT.md](WEBSITE-LOAD-AND-REPORT.md).)

## HTTP

- **Imports:** `import http from 'k6/http'; import { check, sleep, fail } from 'k6'; import { SharedArray } from 'k6/data';`.
- **Calls:** `http.get(url)`, `http.post(url, JSON.stringify(body), { headers: { 'Content-Type': 'application/json' } })`, `http.batch([['GET', url1], ['GET', url2]])`. Read JSON with `r.json('token')` or `r.json('pizza.id')`; timing with `res.timings.duration`.
- **`check()` returns a boolean** for flow control: `const loginOk = check(...); if (!loginOk) { fail('login failed'); }`.
- **Use `!= null` in checks** to catch both null and undefined: `(r) => r.json('token') != null`.
- **Per-request tags:** `{ tags: { endpoint: 'x' } }`; add them only when asked.
- **Globals:** `__VU`, `__ENV`.

## Test data, lifecycle and the execution module

- **`SharedArray`** is loaded once at init, shared read-only across VUs; its initialiser runs once, so keep it cheap: `new SharedArray('users', () => [...])`, or `JSON.parse(open('./data.json'))` for a file.
- **Lifecycle:** `setup()` runs once before VUs start and its return value is passed to the default function and `teardown(data)`. `handleSummary(data)` receives the same data object as the built-in summary.
- **Execution module:** `import execution from 'k6/execution'`. `execution.vu.idInTest` is 1-indexed and unique per VU across all scenarios; `execution.scenario.iterationInInstance`; `exec.scenario.iterationInTest`.

## Custom metrics and the summary

- **Types:** `import { Counter, Gauge, Rate, Trend } from 'k6/metrics'`; `new Counter('pizza_requests')`, `new Gauge('active_vus')`, `new Rate('pizza_success_rate')`, `new Trend('pizza_req_duration_ms', true)`; record with `.add(value)`, for example `successRate.add(ok)` with a check boolean.
- **Thresholds on them:** `pizza_success_rate: ['rate>0.95']`, `pizza_req_duration_ms: ['p(95)<1000', 'avg<500']`, `pizza_requests: ['count>0']`.
- **`textSummary` is not a global;** import it from the k6-summary jslib:

```javascript
import { textSummary } from 'https://jslib.k6.io/k6-summary/0.1.0/index.js';
export function handleSummary(data) {
  return {
    'k6-summary.json': JSON.stringify(data, null, 2),
    stdout: textSummary(data, { indent: '  ', enableColors: true }),
  };
}
```

- **Summary modes:** `--summary-mode` takes `compact` (the default), `full` (adds per-scenario and per-group sections) or `disabled`; tune it with `--summary-trend-stats` and `--summary-time-unit`. `--no-summary` and `--summary-mode=legacy` were removed in v2.0.0 ([end-of-test summary docs](https://grafana.com/docs/k6/latest/results-output/end-of-test/), [VERSIONS.md](VERSIONS.md)).
- **`handleSummary() execution timed out`:** raise `handleSummaryTimeout` (default 120 s) with `handleSummaryTimeout: '5m'` in `options` or `K6_HANDLE_SUMMARY_TIMEOUT` (v2.2.0+, [k6 release notes v2.2.0](https://github.com/grafana/k6/blob/master/release%20notes/v2.2.0.md)).

## Results output

- **Web dashboard and HTML report** (its source moved into the k6 binary in v2.0.0; earlier k6 bundled it as the xk6-dashboard extension): `K6_WEB_DASHBOARD=true k6 run script.js` serves a live dashboard at http://127.0.0.1:5665; `K6_WEB_DASHBOARD=true K6_WEB_DASHBOARD_EXPORT=html-report.html k6 run script.js` also writes a report. Options: `K6_WEB_DASHBOARD_HOST` (default localhost), `K6_WEB_DASHBOARD_PORT` (5665), `K6_WEB_DASHBOARD_PERIOD` (10s), `K6_WEB_DASHBOARD_OPEN` (false), `K6_WEB_DASHBOARD_EXPORT` ([web dashboard docs](https://grafana.com/docs/k6/latest/results-output/web-dashboard/)). The v2.0.0 notes name `k6 run --out=web-dashboard` as the way in.
  - The report has graphs only when the test runs longer than three times the aggregation period.
  - k6 waits to exit while a browser window has the dashboard open; in CI set the port to `-1` to disable it.
- **OpenTelemetry output:** set `K6_OTEL_EXPORTER_PROTOCOL` (`grpc` or `http/protobuf`; it replaced `K6_OTEL_EXPORTER_TYPE` in v2.0.0); basic auth on the HTTP exporter through `K6_OTEL_HTTP_EXPORTER_USERNAME` and `K6_OTEL_HTTP_EXPORTER_PASSWORD`. Rate metrics export as one counter with a `condition` attribute (`nonzero` or `zero`). The v1.7.0 notes recommend the OpenTelemetry output over InfluxDB ([k6 release notes](https://github.com/grafana/k6/tree/master/release%20notes)).
- **Prometheus remote write:** `--out experimental-prometheus-rw`, with static labels from `K6_PROMETHEUS_RW_LABELS="environment=production,server=srv1"` ([k6 release notes](https://github.com/grafana/k6/tree/master/release%20notes)). Querying and dashboarding those metrics is the grafana skill ([grafana SKILL.md](https://github.com/Quegenx/agent-skills/blob/main/skills/monitoring/grafana/SKILL.md)).
- **REST API server:** off by default since v2.0.0 (it used to listen on `localhost:6565`); enable it with `--address=localhost:6565` or `K6_ADDRESS`. From v2.3.0 `/v1/status` includes `execution_result.exit_code`; pair it with `--linger` ([VERSIONS.md](VERSIONS.md)).

## Secrets

Values from a secret source are redacted from k6 logs as `***SECRET_REDACTED***`, unlike values from environment variables or files ([secret source docs](https://grafana.com/docs/k6/latest/using-k6/secret-source/)).

```javascript
import secrets from 'k6/secrets';

export default async function () {
  const token = await secrets.get('cool');
}
```

- **Run with a source:** `k6 run --secret-source=file=file.secret script.js`. Built-in sources are `file` (a `key=value` file), `mock` (secrets from CLI arguments, designed for testing only) and `url`, plus `cloud` for `k6 cloud run --local-execution`; you can pass several. `K6_SECRET_SOURCE` works from v1.7.0.
- **Cloud secrets** are available by default under `k6 cloud run --local-execution` from v2.0.0; opt out with `--no-cloud-secrets`.
- **TOTP:** the grafana/k6 secrets examples pair a secret with `https://jslib.k6.io/totp/1.0.0/index.js`.

## HTML, crypto and encoding

- **HTML:** `import { parseHTML } from 'k6/html'`; jQuery-style `.find('button').size()`, `.text()`, `.toArray().map(el => el.text().trim())`. k6's HTTP client does not execute JavaScript, so an SPA's server HTML shell has no buttons or forms: parse server-rendered pages.
- **Crypto and encoding:** `import { hmac, md5, sha256, randomBytes } from 'k6/crypto'; import encoding from 'k6/encoding';`. `hmac('sha256', SECRET, body, 'hex')`, `md5(body, 'hex')`, `sha256('userpassword', 'hex')`, `encoding.b64encode(randomBytes(16))`, `encoding.b64decode(reqId, 'rawurl', 's')`. All `k6/crypto` functions are synchronous. The global WebCrypto API (`crypto.getRandomValues`) needs no import.

## WebSocket

- **Import** `import { WebSocket } from 'k6/websockets'`; `new WebSocket(url)`; `ws.addEventListener('open'|'message'|'error'|'close', ...)`; `ws.send(...)`, `ws.close()`.
- **The default function must be synchronous:** events resolve in the k6 event loop, and `sleep()` in the main body would block it. Put `sleep()` in the `close` handler.
- **In the error event `e.error` is a string property,** not a method.
- **Thresholds:** `ws_session_duration: ['p(95)<5000']`, `checks: ['rate>0.95']`.

## gRPC

- **Import** `import { Client, StatusOK } from 'k6/net/grpc'`; `client.load(['./proto'], 'quickpizza.proto')`; `client.connect(addr, { plaintext: true })` for non-TLS, `client.connect(addr)` for TLS; `client.invoke('quickpizza.GRPC/Status', {})`; check `r.status === StatusOK` and `r.message`.
- **`client.load()` paths resolve relative to the script file,** not the working directory.
- **With server reflection:** `client.load(null)` and connect with `{ reflect: true }`.
- **Close per iteration:** `try/finally` with `client.close()` in `finally`. Threshold: `grpc_req_duration: ['p(95)<500']`.

## xk6 extensions

- **Import, then run with plain `k6`** (k6 v1.2.0+): auto extension resolution provisions Official and Community extensions from the import, for example `import faker from 'k6/x/faker'` then `k6 run script.js` ([running extensions](https://grafana.com/docs/k6/latest/extensions/run/)). It doesn't cover output extensions, scripts read from stdin, or files other than `.js`, `.ts` or `.tar`; disable it with `K6_AUTO_EXTENSION_RESOLUTION=false`. This line used to make an xk6 build the only path.
- **Build a custom binary** only for other extensions (including your own), output extensions and stdin scripts: `xk6 build --with github.com/grafana/xk6-<name>@latest -o ./k6-with-<name>`, then `./k6-with-<name> run k6/scripts/<name>-test.js`. Whether auto resolution covers xk6-sql's `CGO_ENABLED=1` SQLite build is not verified; keep its build line below. One-shot extension checks use `checks: ['rate==1']`.
- **Extension authors:** the Go module is `go.k6.io/k6/v2` since v2.0.0 ([VERSIONS.md](VERSIONS.md#v200-migration-checklist)).

## Docs lookup

- **`k6 x docs`** serves docs for the installed k6 version (it may lag the target version when migrating). Calls: `$DOCS_CMD <path> 2>/dev/null`, `--depth 2`, `search <term>`. Always redirect stderr (provisioning log lines); never pipe through `head` (it truncates). Paths take spaces or slashes; the full parent path is required (`using-k6 thresholds`, not `thresholds`); the `k6-` prefix is added automatically on `javascript-api` paths. Aim for 2 calls; a wrong path returns subtopics.
- **Common paths:** `javascript-api k6-http`, `k6-browser`, `k6-websockets`, `k6-net-grpc`, `k6-metrics`, `k6-data`, `k6-execution`, `k6-crypto`, `k6-encoding`, `k6-html`; `using-k6 scenarios`, `using-k6 thresholds`, `using-k6 checks`, `using-k6 test-lifecycle`; `cloud`; `best-practices`.
- **The TTY question is disputed.** The k6 skill says it renders only with a TTY and wraps it: macOS `DOCS_CMD="script -q /dev/null k6 x docs"`, Linux `DOCS_CMD="script -qc 'k6 x docs' /dev/null"`; output saying "k6 documentation is a directory of markdown files" means the wrapper isn't working, so fall back to `https://grafana.com/docs/k6/latest/`. The browser-test skill says recent xk6-docs serves plain markdown without a TTY, so call `k6 x docs` directly and wrap only if your build prints an interactive guide or ANSI.
- **The minimum version is k6 v1.7.0:** its release notes add automatic resolution for subcommand extensions, provisioning the binary on demand ([k6 release notes v1.7.0](https://github.com/grafana/k6/blob/master/release%20notes/v1.7.0.md)). The setup guide agrees (auto-provisioned on first use, about 30 s, then cached; `k6 x docs --version v1.6.1` as the fallback on 404; for older k6 `go install go.k6.io/xk6/cmd/xk6@latest` then `xk6 build --with github.com/grafana/xk6-subcommand-docs@latest -o ./k6-with-docs`, Go 1.21+). The browser-test skill said `k6 x` needs k6 v2+ ("your k6 is older than v2, where `k6 x` isn't available"); the release notes settle it for v1.7.0.
- **`k6 x` with no argument lists the subcommands** (v2.1.0+): `agent` ("Bootstrap an AI-assisted k6 testing workflow in any editor"; what it does was not checked), `docs`, `explore` and `mcp` (an MCP server for k6) ([k6 release notes v2.1.0](https://github.com/grafana/k6/blob/master/release%20notes/v2.1.0.md)).
- **mcp-k6,** when configured (one of the install options in the grafana/mcp-k6 README is an xk6-built `k6 x mcp` subcommand): `validate_script` and `get_documentation` (for example `get_documentation("best_practices")`, `get_documentation("javascript-api/k6-browser")`). Check it is available, fall back to `k6 x docs`, then a web fetch.

## Prove it

- The script is on disk at `k6/scripts/<name>.js` with the generated-by line, and the validation command from the table exits 0 (or 99 for a pure threshold breach under load).
- Every request has a `check()` or `expect()`, every load test has `http_req_duration` and `http_req_failed` thresholds, and a threshold on `checks` exists wherever checks matter.
- `grep -nE '^(let|var) ' <script>` finds nothing; no `k6/ws`, `k6/experimental/websockets` or `k6/experimental/redis` import; no secret literal outside `__ENV` or `k6/secrets`.
- A CI run that enables the web dashboard sets `K6_WEB_DASHBOARD_PORT=-1`, so k6 never waits on an open dashboard window.
- gRPC and browser iterations close their client or page in `finally`; WebSocket `JSON.parse` sits in `try/catch`.
