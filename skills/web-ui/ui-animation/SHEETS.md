# Sheets

## A swipeable sheet on native scroll

The React Aria Sheet ("Scrolling is All You Need: Building a Swipeable Sheet") is an overlay that slides in from an edge and is swiped away, "entirely built using native CSS scroll snapping and view timelines, on top of our existing Modal component". The scroll is the gesture: "swipe gestures run off the main thread at the native display refresh rate without any JavaScript touch handling, and we get fluid momentum scrolling and elastic physics for free." The Motion drag in [PATTERNS.md](PATTERNS.md#gestures-drag-throw-snap) handles the gesture in JavaScript; here the browser's scrolling does it.

- **The overlay is a scroller twice the viewport's height:** a scrollable element above the page, scrollbar hidden with `scrollbar-width: none`, positioned so only its top half is visible, with the sheet in the bottom half. The sheet sits in a "stage", a viewport-sized flex container that puts it on the viewport's edge (the bottom, say).
- **Snap points at the sheet's top and bottom,** with CSS scroll snap, so it always stops fully open or fully closed.
- **Closed is scroll position zero:** the sheet is off screen, clipped by the window viewport. Opening scrolls to 100% with `scroll-behavior: smooth`, which animates the sheet up into view; swiping it away is scrolling to the top.
- **Unmount once it's out of view,** detected with an `IntersectionObserver`.
- **Stretch past the edge with padding:** for native rubber-band scrolling, the `overscrollPadding` prop adds padding to the sheet's edge "so that it appears to stretch beyond the viewport when dragged".
- **One geometry, four edges:** everything flips with the `swipeDirection` and `position` props, for top, left, right and center sheets.
- **Animate with the swipe, not after it:** the backdrop and the sheet take a `swipeAnimation`, a CSS keyframe animation synchronized with the gesture (the backdrop fades; the sheet transforms or changes its corner radius with swipe progress). It runs on CSS `view-timeline`, which tracks how much of an element is visible, with `view-timeline-inset: 0 100dvh` "so that swipe animations begin when the sheet is visible, not when clipped by the window viewport".
- **Partial heights are 1px markers:** `snapPoints` stop the sheet partially open at given visible heights. Each one is an invisible 1px absolutely positioned div inside the sheet; `scroll-margin-top: 100dvh` makes the marker snap to the bottom of the viewport, leaving that height on screen.
- **Partly open, a swipe anywhere expands it:** the inner content gets `overflow: hidden` until the sheet is fully open, then becomes scrollable.
- **Scroll chaining is the dismiss gesture:** `overscroll-behavior: auto` on the inner content means a swipe down at the top of the content dismisses the sheet, and after scrolling the content, a swipe down scrolls the content. The `app-ui` skill's sheets don't swipe and set `overscroll-behavior: contain` ([app-ui OVERLAYS.md](https://github.com/Quegenx/agent-skills/blob/main/skills/web-ui/app-ui/OVERLAYS.md)).
  - Inner scrollers bounce too now: "Chrome 145 joins WebKit and Firefox in supporting **overscroll effects** on nested scrollers" ([nerdy.dev: Overscroll Effects On Nested Scrollers In All Browsers](https://nerdy.dev/overscroll-effects-on-nested-scrollers-in-all-browsers), 2026-01-21). MDN's `overscroll-behavior` page still shows Limited availability ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overscroll-behavior)).
  - Flutter: swiping down at the top of a sheet's list to close it, and a spring sheet that keeps a fling's speed, are in [flutter-ux NAVIGATION-AND-SHEETS.md](https://github.com/Quegenx/agent-skills/blob/main/skills/mobile/flutter-ux/NAVIGATION-AND-SHEETS.md#swipe-down-at-the-top-to-close).
- **Can't dismiss, can still snap:** with `preventDismissal` the user can't swipe it away but can swipe between snap points. After the entering animation the stage is adjusted so the bottom of the viewport aligns with the first snap point at `scrollTop = 0`; that stops it leaving the screen and "preserves the native feeling scroll bounce".
- **Stacked sheets share the swipe timelines:** a custom `stackAnimation` runs on the same view timelines, declared on the root `html` element with `timeline-scope` so any element can use them. Each sheet gets one instance per sheet in front of it, tied to that sheet's timeline, and `animation-composition: accumulate` adds them up, so each sheet looks one level deeper.
- **Keep the bottom reachable above the software keyboard:** the keyboard, "especially on iOS", appears on top of content rather than pushing it and often scrolls the whole page when it opens, and the dynamic viewport units don't adjust for it. The sheet's scrollable content gets `padding-bottom: calc(100dvh - var(--visual-viewport-height))`, so the bottom content can be reached while it still scrolls behind the keyboard. React Aria's `usePreventScroll` hook was improved to reduce the layout shifts as the keyboard opens and closes; tapping an input inside a Sheet opens the keyboard and scrolls the input into view without scrolling the entire page.
  - Flutter: a form in `showModalBottomSheet` that the keyboard covers is in [flutter-ux KEYBOARD-AND-FOCUS.md](https://github.com/Quegenx/agent-skills/blob/main/skills/mobile/flutter-ux/KEYBOARD-AND-FOCUS.md#forms-in-a-bottom-sheet).
- **The ingredients:** "combining scroll snapping, view timeline animations, overscroll-behavior, and dynamic viewport units".
  - The same set builds pull-to-refresh: `html { scroll-snap-type: y mandatory; overscroll-behavior: contain; scroll-behavior: smooth; }`, an indicator pulled in on `view()` `exit` ranges, and `scrollend` to act when the gesture ends; the author calls it "a prototype and isn't production ready" ([nerdy.dev: Pull to Refresh](https://nerdy.dev/pull-to-refresh-prototype-with-scroll-snap-and-scroll-driven-animation), 2023-06-28).
  - Diagonal drags lock to one axis in a scroller; `scroll-axis-lock: none` (Chrome 153 per the post, no MDN page yet) unlocks them, and swipe to dismiss is among its uses. The author still found it "a bit clumsy" and filed performance regressions ([nerdy.dev: Scroll Axis Lock](https://nerdy.dev/css-scroll-axis-lock), 2026-08-10). Both recipes are in [modern-css SCROLL.md](https://github.com/Quegenx/agent-skills/blob/main/skills/web-ui/modern-css/SCROLL.md).

The article states no focus, Escape or reduced-motion rules beyond building on its Modal; the ones in [PATTERNS.md](PATTERNS.md#modals-sheets-popovers) still apply.
