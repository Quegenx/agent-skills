## The rules

1. **Use an Effect only to sync with something outside React.** Compute derived values during render, reset with a `key`, and run an action's work in its handler: "Use Effects only for code that should run *because* the component was displayed to the user" (https://react.dev/learn/you-might-not-need-an-effect; [EFFECTS-AND-STATE.md](EFFECTS-AND-STATE.md#you-might-not-need-an-effect)).
2. **Never suppress the dependency linter.** "By suppressing the linter, you 'lie' to React about the values your Effect depends on" (https://react.dev/reference/react/useEffect). Move the value inside the Effect or out of the component, or read it from an Effect Event, which never goes in the deps and has no stable identity ([EFFECTS-AND-STATE.md](EFFECTS-AND-STATE.md#useeffectevent)).
3. **Keys come from the data,** never from the index of a list that can change or from `Math.random()`, and components are declared at the top level, never inside another component (https://react.dev/learn/rendering-lists; [EFFECTS-AND-STATE.md](EFFECTS-AND-STATE.md#keys-and-component-identity)).
4. **For server-rendered web surfaces, the server render and the first client render match.** Read browser-only values through `useSyncExternalStore` with a server snapshot or a two-pass render; `suppressHydrationWarning` is only for text that must differ, one level deep (https://react.dev/reference/react-dom/client/hydrateRoot; [EFFECTS-AND-STATE.md](EFFECTS-AND-STATE.md#hydration-safe-reads)).
5. **Measure before memoizing, and check the React Compiler first.** "A high render count is evidence, not a defect" [React Doctor, performance]; with the compiler on, leave existing memoization in place or test before removing it (https://react.dev/learn/react-compiler/introduction; [RERENDERS-AND-COMPILER.md](RERENDERS-AND-COMPILER.md#the-react-compiler)).
6. **A provider passes a value that keeps its identity,** and `memo` does not shield consumers from a new one (https://react.dev/reference/react/useContext; [RERENDERS-AND-COMPILER.md](RERENDERS-AND-COMPILER.md#context)).
7. **A state set after `await` in a Transition gets its own `startTransition`,** and a Transition never debounces, cancels work or controls a text input (https://react.dev/reference/react/useTransition; [RERENDERS-AND-COMPILER.md](RERENDERS-AND-COMPILER.md#transitions)).
8. **Reach for props, then children, then context,** and give each mode its own component instead of a boolean prop ([COMPOSITION.md](COMPOSITION.md)).
9. **Every Server Action authenticates and authorizes inside itself;** treat it as a public endpoint ([NEXTJS.md](NEXTJS.md)).
10. **An audit never edits code:** it writes findings with evidence at `path:line` and plans, and the scanner supplies evidence while the audit supplies leverage [React Doctor, improve-react] ([AUDIT.md](AUDIT.md)).

## Prove it

`eslint-plugin-react-hooks` (its `recommended` preset) reports nothing on the files you touched and the diff adds no `eslint-disable` for hooks rules; every Effect in the change syncs with an outside system; a changed server-rendered web page hydrates with no mismatch warning; list items keep their input and focus across reorder; a Profiler recording in a production build shows the interaction you optimized got faster, with the React Compiler's status recorded; and every file's own Prove it checks pass for the parts you touched.
