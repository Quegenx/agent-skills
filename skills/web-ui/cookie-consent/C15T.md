# c15t setup

c15t is an open-source consent manager (Apache-2.0) with a banner, a preference dialog, consent-gated scripts for "30+ vendors" and consent records stored by Inth or a backend you run. "A working setup takes four steps in every framework: install c15t, point it at your Inth project's backend URL, mount the consent components once near the root of your app, and move your analytics and marketing scripts into c15t so they wait for consent. Then verify it by watching network requests, not just the banner." Source: https://c15t.com/docs/index.md, choose-your-setup.md, the Next.js and React quickstarts, troubleshooting.md and the hosted setup skill https://c15t.com/SKILL.md, all `[c15t]`.

## Choose the setup

"Tell the agent your framework, router and hosting before it picks a recipe. A Next.js App Router app on Vercel and a static Astro site need different setups." [c15t, docs/index.md] Selected rows from choose-your-setup.md:

| Your app | Setup |
|--|--|
| Next.js App Router with a Next.js server | Server resolves consent from a build-time manifest and streams it to the page |
| Next.js with static, ISR, `'use cache'` or `ensureStatic = 'navigation'` pages | Browser resolves consent on those pages |
| Next.js with `output: 'export'` | Browser resolves consent |
| React with Vite, or another single-page app | Browser resolves consent |
| React Router framework mode, Remix, or another server-rendered React app | Browser resolves consent after hydration |
| Plain HTML, a CMS, a page builder, or a static site generator such as Hugo or Eleventy | One script tag, stock banner included |
| Your own UI, or a framework without an adapter such as Solid | Headless runtime |

Backend options and the server-vs-browser tradeoff are in [CONSENT-STATE.md](CONSENT-STATE.md#who-runs-the-backend). Each package ships its docs: "agents can read `node_modules/c15t/AGENTS.md` for an index of version-matched guides", and every page has a Markdown version listed in https://c15t.com/docs/llms.txt.

## Install at exact versions

[c15t, SKILL.md §5]

- Resolve `c15t@latest` (and `@c15t/integrations@latest` when a vendor helper is used) with the project's package manager (`npm view <package>@latest version`, `pnpm view ...`, `yarn npm info <package>@latest --fields version`, `bun info ...`), then "Install each at its exact resolved version ... Never install by tag or without a version."
- "A tagged install can resolve to an older release per package when the package manager delays new releases (pnpm's `minimumReleaseAge`), and mixing releases installs two copies of the consent engine."
- Check "exactly one version of `@c15t/core`" (`npm ls @c15t/core`, `pnpm why @c15t/core`, `yarn why @c15t/core`, `bun why @c15t/core`). "Two copies keep two separate consent states. Do not add overrides or resolutions to force it".
- "Mount one consent provider at the app root, outside route components; two providers keep two separate choices." [c15t, SKILL.md §5c]
- npm's `latest` tag is c15t 3.1.0 (`npm view c15t dist-tags`, 2026-10-18), matching the hosted skill's statement that the docs describe "the c15t release on the `latest` npm dist-tag". (c15t's troubleshooting page says "npm's `latest` tag still points to c15t v2" and that a plain install gets v2; that line is stale.)

## Next.js App Router

[c15t, https://c15t.com/docs/frameworks/next/quickstart.md] Install `c15t @c15t/integrations`. There is no stylesheet to import.

```sh title=".env.local"
NEXT_PUBLIC_C15T_BACKEND_URL=https://your-project.inth.app
```

"The URL is public configuration, not a secret." Wrap the config so the build bundles the policy:

```ts title="next.config.ts"
import { withConsentManifest } from 'c15t/next/build';
import type { NextConfig } from 'next';

const nextConfig = {} satisfies NextConfig;

export default withConsentManifest(nextConfig);
```

```ts title="c15t.config.ts"
import { posthog } from '@c15t/integrations/posthog';
import { defineConsentConfig } from 'c15t/next';

export default defineConsentConfig({
	scripts: [
		posthog({
			id: 'phc_your_project_key',
			initOptions: { cookieless_mode: 'never' },
			loadMode: 'after-consent',
		}),
	],
});
```

"The file is bundled into the browser as well as the server, so it can hold `scripts` but must hold no secrets." Then the root layout:

```tsx title="app/layout.tsx"
import {
	ConsentBanner,
	ConsentDialog,
	ConsentDialogLink,
	ConsentRoot,
} from 'c15t/next';
import { resolveConsent } from 'c15t/next/server';
import type { ReactNode } from 'react';

import './globals.css';

const RootLayout = ({ children }: { children: ReactNode }) => (
	<html lang="en">
		<body>
			{/* Not awaited: the page renders while consent resolves. */}
			<ConsentRoot state={resolveConsent()}>
				{children}
				<ConsentBanner />
				<ConsentDialog />
				<footer>
					<ConsentDialogLink>Privacy settings</ConsentDialogLink>
				</footer>
			</ConsentRoot>
		</body>
	</html>
);

export default RootLayout;
```

- "`ConsentRoot` already wraps `ConsentProvider`, so don't mount both." The components are client components, so "you write no `'use client'` wrapper".
- "Until the browser applies it, the banner stays hidden and optional categories stay denied." "The App Router's default streamed path does not include the banner in initial HTML." [c15t, comparisons/build-your-own.md]
- "Remove any existing PostHog loader, including `next/script` and tag-manager entries, so the integration loads once." Why `beforeInteractive` scripts escape the consent manager is in [react NEXTJS.md](https://github.com/Quegenx/agent-skills/blob/main/skills/web-ui/react/NEXTJS.md#nextscript).
- Check: `next build` and `next start`; "The browser makes no `/init` request, and choices post to `${backendURL}/subjects`."

## React with Vite

[c15t, https://c15t.com/docs/frameworks/react/quickstart.md]

```ts title="vite.config.ts"
import react from '@vitejs/plugin-react';
import { consentManifest } from 'c15t/build';
import { defineConfig } from 'vite';

export default defineConfig({ plugins: [react(), consentManifest()] });
```

```tsx title="src/consent.tsx"
import { posthog } from '@c15t/integrations/posthog';
import {
	ConsentBanner,
	ConsentDialog,
	ConsentDialogLink,
	ConsentProvider,
	hosted,
} from 'c15t/react';
import type { ReactNode } from 'react';

const options = {
	// Asks VITE_C15T_BACKEND_URL for each visitor's policy.
	mode: hosted(),
	scripts: [
		posthog({
			id: 'phc_your_project_key',
			initOptions: { cookieless_mode: 'never' },
			loadMode: 'after-consent',
		}),
	],
};

export const Consent = ({ children }: { children: ReactNode }) => (
	<ConsentProvider options={options}>
		{children}
		<ConsentBanner />
		<ConsentDialog />
		<footer>
			<ConsentDialogLink>Privacy settings</ConsentDialogLink>
		</footer>
	</ConsentProvider>
);
```

- Set `VITE_C15T_BACKEND_URL` "before you build, not when you serve the files." The plugin adds a script to `index.html` "that sends `/init` while your JavaScript downloads, so the banner shows sooner."
- "Keep `Consent` mounted for the life of the app. If you use a client-side router, render the router inside `Consent` so navigation does not remount the provider."
- PostHog "uses its EU host; add `region: 'us'` for a US project."

## Gate your own features

```tsx
import { useConsent } from 'c15t/react';

export function MarketingBanner() {
	return useConsent('marketing') ? <aside>Spring sale</aside> : null;
}
```

"`useConsent` returns the permission right now. Under an opt-out policy it can be `true` before the visitor has chosen anything." For iframes, use `ConsentGate` [c15t, react/quickstart.md].

## Upgrade and replace paths

[c15t, SKILL.md §2, §5a, §5b] Classify first: c15t packages all 3.x, keep; any below 3.0, upgrade; none, but another consent manager or a homegrown banner, replace; nothing, install.

- **Upgrade:** "Upgrade before any other change. v3 renamed most v2 APIs, and editing v2 code by hand produces a mix of both." Run the guide's codemod "exactly as the guide writes it, with every listed transform, first with `--dry-run`, then for real", then resolve every `TODO(c15t v3)`. "a v3 client cannot read a v2 backend, so both must ship together."
- **Replace:** record the old manager's categories, storage key, callbacks and every caller; map categories by purpose; move every caller and delete the old banner, its storage reads and its callbacks. "Old stored choices do not carry over unless the c15t docs describe an import; visitors choose again." Coming from a boolean cookie: "Review what visitors previously accepted before you create category or vendor grants." [c15t, comparisons/react-cookie-consent.md]
- Then move each tool behind consent: [SCRIPT-GATING.md](SCRIPT-GATING.md).

## Troubleshooting

"Start with three checks" [c15t, troubleshooting.md]:

1. **Which c15t is running.** `window.c15t` in the console prints `{ version, pkg, mode, hosting }` in v3; "`undefined` means no c15t provider has mounted on this page. A `window.c15tStore` object means the page runs v2."
2. **The backend request.** Filter Network by the backend URL; "A CORS error means the backend does not trust your site's origin." Requests to `your-project.inth.app` that fail mean the placeholder URL is still in the code.
3. **Consent state.** The c15t DevTools panel "shows the resolved policy, whether a prompt is needed, each category's permission and the scripts c15t manages."

- "Do not 'fix' a missing banner by granting every category or turning c15t off. While the policy is unresolved, every optional category stays denied. Turning the runtime off lets optional scripts load."
- A banner in the DOM but invisible: c15t's rules are missing (`styles: false` without the stylesheet, a CSP blocking its `<style>` elements, Tailwind CSS 3's preflight).
- "A static host serves files only." "Point the browser at the absolute backend URL from Inth instead of a same-origin `/api/c15t` path, then test the built output with a static file server, not the dev server."
- Policy-side reasons for no banner are [CATEGORIES-AND-POLICIES.md](CATEGORIES-AND-POLICIES.md#why-the-banner-may-be-absent).

## Prove it

`npm ls @c15t/core` (or the package manager's equivalent) shows one version; `window.c15t` prints a v3 object with the expected `mode`; one provider is mounted; the backend request succeeds without a CORS error from every trusted origin (production, previews, local); the config file holds no secrets; and the release check in [VERIFY-CONSENT.md](VERIFY-CONSENT.md) passes on the production build.
