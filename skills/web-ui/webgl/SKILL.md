# WebGL

WebGL on a live page runs on hardware you don't control: contexts get evicted and lost, GPUs are blocklisted or switched off, displays run at 120Hz and fractional scales, and server rendering imports the module where there is no `window`. So the fallback is part of the product, the loop runs only while something visible changes, and the cost per pixel decides the resolution. Sources: [flornkm, webgl-components] for widgets and the GPU probe (MIT), [React Doctor, improve-threejs] for the Three.js and R3F audit (Modified MIT), and [webdown-a, 3d-site] for 3D launch pages, each corrected against the Khronos WebGL spec, MDN, threejs.org and the R3F docs where they disagree. Whether a canvas is the right tool at all is in [web-performance BROWSER.md](https://github.com/Quegenx/agent-skills/blob/main/skills/web-ui/web-performance/BROWSER.md#real-dom-or-canvas); WebGL in code-made video (drawn from `seek(t)`, rendered in software) is in [seek-engine SHADERS.md](https://github.com/Quegenx/agent-skills/blob/main/skills/videos/seek-engine/SHADERS.md), and the rules that differ are listed in [WIDGETS.md](WIDGETS.md#live-page-vs-video).

## The rules

1. **For repeated shader widgets, one WebGL context and one rAF loop for every instance on the page.** Blit from the shared canvas into cheap 2D canvases within the same task as the draw. [flornkm, webgl-components] ([WIDGETS.md](WIDGETS.md#one-context-many-instances))
2. **Draw only while something visible changes.** Gate instances on `IntersectionObserver`, pause when the tab is hidden, cap slow ambient drift at 30fps, and use `frameloop="demand"` with `invalidate()` for an R3F scene that changes only on input. [flornkm, webgl-components]; [React Doctor, improve-threejs] ([WIDGETS.md](WIDGETS.md#frame-loop), [THREEJS-AND-R3F.md](THREEJS-AND-R3F.md#p2-per-render-or-per-interaction-waste))
3. **Rank by where code runs.** Allocation or `setState` inside `useFrame` or a rAF callback outranks a bigger mistake in a settings panel. [React Doctor, improve-threejs] ([THREEJS-AND-R3F.md](THREEJS-AND-R3F.md#severity-follows-the-render-loop))
4. **Let the shader's cost decide the pixel ratio,** after the shader is final; for a three.js scene, size the buffer yourself and cap its pixel count instead of `setPixelRatio(window.devicePixelRatio)`, which the manual calls "strongly NOT RECOMMENDED". [flornkm, webgl-components]; https://github.com/mrdoob/three.js/blob/dev/manual/pages/responsive.html ([WIDGETS.md](WIDGETS.md#resolution-and-dpr), [THREEJS-AND-R3F.md](THREEJS-AND-R3F.md#resize-and-pixel-ratio))
5. **For the shader-widget branch, refuse software rendering and ship the fallback as a product surface:** `failIfMajorPerformanceCaveat: true`, a `fallback` prop in every example, a `forceFallback` demo, and a positioned clipping frame. [flornkm, webgl-components] ([WIDGETS.md](WIDGETS.md#the-fallback-is-a-production-surface))
6. **Handle context loss both ways:** call `preventDefault()` on `webglcontextlost` only if you rebuild every resource on `webglcontextrestored`; otherwise stay on the fallback. https://registry.khronos.org/webgl/specs/latest/1.0/ ([WIDGETS.md](WIDGETS.md#context-loss-and-restore))
7. **Dispose what the framework does not.** three.js frees nothing on removal; R3F disposes JSX objects on unmount but not `<primitive>` objects; watch `renderer.info.memory`, not only the JS heap. https://github.com/mrdoob/three.js/blob/dev/manual/pages/how-to-dispose-of-objects.html, https://r3f.docs.pmnd.rs/api/objects ([THREEJS-AND-R3F.md](THREEJS-AND-R3F.md#disposal))
8. **Mark colour textures sRGB and data textures not;** the renderer's `outputColorSpace` already defaults to `SRGBColorSpace`. https://threejs.org/docs/pages/WebGLRenderer.html ([THREEJS-AND-R3F.md](THREEJS-AND-R3F.md#causes-per-rubric-row))
9. **Keep content out of the canvas.** On a launch page the content system works without the scene, without JavaScript and with WebGL off, and an asset error breaks only its own scene. [webdown-a, 3d-site] ([LAUNCH-SITES.md](LAUNCH-SITES.md#failure-layers-and-state))
10. **Load through cached three.js loaders:** one `DRACOLoader`, `KTX2Loader.detectSupport(renderer)` before the first texture, `HDRLoader` (not the renamed `RGBELoader`) for HDR environments. https://threejs.org/docs/pages/KTX2Loader.html, https://threejs.org/docs/pages/HDRLoader.html ([LAUNCH-SITES.md](LAUNCH-SITES.md#loaders))
11. **Reduced motion keeps the look and stops the motion:** one still frame at full fidelity for a widget; no orbiting, scroll-scrubbed or shader-heavy transitions for a scene. [flornkm, webgl-components]; [webdown-a, 3d-site] ([WIDGETS.md](WIDGETS.md#accessibility-and-layout), [LAUNCH-SITES.md](LAUNCH-SITES.md#visual-system))
12. **No visual finding without evidence:** a screenshot, frame capture or reproduced observation, or a label saying it was inferred from source. [React Doctor, improve-threejs] ([THREEJS-AND-R3F.md](THREEJS-AND-R3F.md#the-audit-workflow))

## Prove it

Apply the selected branch's acceptance checks to the surface changed, and report checks not performed as unverified. For the shader-widget branch, [scripts/gpu-probe.html](scripts/gpu-probe.html) reports the branch you expect on each target machine; Chrome with `--disable-gpu` shows every fallback clipped to its frame and the content readable; a forced context loss flips to the fallback (and back, if you restore); tab-hidden CPU sits near zero and an idle demand-loop scene renders no frames; `renderer.info.memory` stays flat across mount and unmount; the canvas has non-black, non-transparent pixels after load at desktop and mobile sizes; reduced motion shows a still, full-fidelity frame; a production build serves the page; and every file's own Prove it checks pass for the parts you touched.
