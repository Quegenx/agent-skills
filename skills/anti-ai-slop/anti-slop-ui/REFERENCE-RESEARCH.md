# Research references for a specific design decision

Use this when the job is finding alternatives before building or reworking a surface. Gather supplies the research method: start with the user's material, inspect the actual references, and name the part each one contributes. Exact reconstruction stays with [pixel-reverse-engineer](https://github.com/Quegenx/agent-skills/blob/main/skills/web-ui/pixel-reverse-engineer/SKILL.md); building a selected design stays with [FROM-DESIGN.md](FROM-DESIGN.md). [gather, SKILL.md; sources.md]

## Name what the search must answer

[gather, SKILL.md, Name the brief and Start with what the user gave]

- Name the surface, platform and property to study: layout, navigation, density, type, color or motion. Split a broad brief into its parts and search their short synonyms.
- Start with the tabs, screenshots, links and design files already supplied, then relevant saves in the user's available library. Inspect those before searching outside it.
- Search the platform being designed. A phone screen is not evidence for how a desktop toolbar behaves.
- Keep the requested scope: a reference for a top bar does not authorize taking the whole app's look. Preserve accepted owner designs and the [existing direction rules](SKILL.md#1-direction-first).

## Collect and inspect

[gather, SKILL.md, Search every source at once and Look at every reference]

- Search relevant available sources in parallel. The source requires a fixed number of services and a connection question for each missing one; this optional method does not make those accounts a prerequisite for using the material already available.
- Use supplied screenshots or the closest saved reference to seed visual searches where supported. Text search alone can miss the quality the user pointed at.
- Look at the actual image or moving media and the named part. A title, tag or gallery preview alone does not establish that the reference fits.
- When a selected reference is a reachable shipped product, capture the relevant part on its live surface. Keep the original link with that capture.
- Group the candidates by the decision they help answer. Each kept item carries its source, a note naming the specific part to take and a clear Shipped or Concept label. A concept is an option to explore, not evidence of a working product.
- Keep close alternatives available for the user's choice rather than disguising a taste decision as a verified finding. Fixed minimum reference counts, source counts and board tooling are gather's production choices, not completion criteria here.

## Follow a pick without repeating the board

[gather, SKILL.md, Act on what comes back and Save what the user keeps]

For “more like this,” use the selected image as the visual seed, keep its group and exclude URLs already shown. Keep the user's notes with the pick so the next step knows what attracted them. Save selected items to an external library or board only when requested; inspect the destination's existing organization and skip duplicates.

A reference collection supports a decision. It does not replace a [working variant](VARIANTS.md), source inspection or verification of the real interface. State unreachable sources and uninspected media plainly. Existing browser and research tools govern sign-in and service limits; do not route around them. [gather, SKILL.md; anti-slop-ui, SKILL.md]

## Prove it

[gather, SKILL.md, Look at every reference and Reporting]

The collection answers a named surface decision on the right platform. Every kept reference was inspected, links to its source, names the part to take and distinguishes a concept from shipped work. Additional results exclude earlier URLs. Unavailable sources remain unverified, and no research choice silently changes a protected design.
