# Extract a working web technique

Turn working code or a supplied prompt article into reusable instructions, preserving the mechanism, its failure modes and the evidence boundary. Sources: [MengTo/Skills, web-technique-to-skill/SKILL.md; article-prompts-to-skills/SKILL.md]. This repository's existing folder format, permissions and verification policy govern publication.

## Find the mechanism and its owner

- Start from the working implementation when available. Write the operation whose removal breaks the effect; check whether it survives a different subject, palette and layout. A visual theme alone does not establish a reusable mechanism. [MengTo/Skills, web-technique-to-skill/SKILL.md, Name the mechanism in one sentence]
- Separate mechanism, demo staging and incidental details. Preserve mathematics, state, ordering and budgets; keep palette, copy and scenery with their reference context; remove project selectors and accidental paths from reusable instructions. Search the existing library and extend the nearest owner before creating another definition. [MengTo/Skills, web-technique-to-skill/SKILL.md, Split mechanism from staging; Declare the boundary in the opening lines]
- For article or prompt sources, make a capability ledger: keep, remove, combine or split each requested behavior, with a reason and the evidence that could demonstrate it. Split independent ideas and keep coupled behavior together. A polished static workflow illustration must be labeled as an illustration, rather than proof that the workflow executed. [MengTo/Skills, article-prompts-to-skills/SKILL.md]
- Give the skill's opening a concrete boundary against its closest neighbor and a source-context line identifying the original project and the mechanism's job there. [MengTo/Skills, web-technique-to-skill/SKILL.md, Declare the boundary in the opening lines; Record where the design came from]

## Preserve the hard-won details

- Name the visible failure each rule prevents. Keep expensive gotchas about color conversion, layout readiness, stacking contexts, operation order and platform behavior beside that symptom. A decorative adjective is not an acceptance condition. [MengTo/Skills, web-technique-to-skill/SKILL.md, Anchor every rule to the failure it prevents; Keep the expensive gotchas]
- Carry the actual tuned constants, ranges, timing, easing, per-layer settings and budgets. Distinguish measured values from visual choices and report measurement conditions. Use a small table when several parameters vary together. [MengTo/Skills, web-technique-to-skill/SKILL.md, Carry numbers, not adjectives]
- Verify the stack through imports, renderer construction and context creation. Distinguish the effect renderer from the CSS or component interface around it. A Canvas 2D demo does not demonstrate a WebGL implementation merely because its source article discusses shaders. [MengTo/Skills, web-technique-to-skill/SKILL.md, Name the demo and disclose the stack]
- Explain the measured bottleneck, the useful lever and the tradeoff. Keep shared lifecycle rules in [webgl WIDGETS.md](https://github.com/Quegenx/agent-skills/blob/main/skills/web-ui/webgl/WIDGETS.md#frame-loop) rather than repeating them in each extracted technique. The source's DPR 2 and approximately 1/30-second delta clamp are its starting presets, not universal requirements. [MengTo/Skills, web-technique-to-skill/SKILL.md, Fold in accessibility and lifecycle; State the cost honestly]

## Describe an honest demonstration

- Name the concrete technique and verified stack on the first screen. If approved layout-defining copy must remain, put the technique and stack in the browser title and an existing secondary label rather than changing that composition. [MengTo/Skills, web-technique-to-skill/SKILL.md, Name the demo and disclose the stack]
- When exact recreation is authorized, inventory the reference layer by layer and compare geometry, crop, scale, alignment, palette, type, assets and motion hierarchy. Reuse only the owned or licensed generators/assets necessary for fidelity, recording provenance. A minimal local bundle can be preferable to a one-file approximation. Client identity, purchased media and licensed fonts do not become redistributable by appearing in a source. [MengTo/Skills, web-technique-to-skill/SKILL.md, Direct the demo]
- Use controls that expose meaningful states, real form elements, visible focus and keyboard access. The source asks for a designed reduced-motion still with usable controls. Keep a separate accessible cue when the mechanism communicates state. [MengTo/Skills, web-technique-to-skill/SKILL.md, Fold in accessibility and lifecycle; Direct the demo]
- Preserve minimal, exact-recreation and remix prompt branches when useful. A remix changes subject, palette and composition while preserving the mechanism and its budgets. Neither this optional demo workflow nor the source's mandatory preview files authorizes builds or browser execution in a documentation-only task. [MengTo/Skills, web-technique-to-skill/SKILL.md, Package and commit; article-prompts-to-skills/SKILL.md]

## Prove it

The mechanism survives a change of staging; its nearest owner is identified; every retained constraint traces to implementation or source evidence; constants retain their conditions; the disclosed stack matches the implementation; and asset provenance is recorded. When runtime verification is authorized, check representative states, forward/reverse traversal, fast skips, reload at depth, keyboard access and reduced motion. The source uses 1440 by 900 and 390 by 844 as demo viewports; report the actual viewports and checks used, including anything unrun. [MengTo/Skills, web-technique-to-skill/SKILL.md, Verify in a browser, then report; Verify]
