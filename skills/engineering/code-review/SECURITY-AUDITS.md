# Security audit evidence

This contract comes from [cloudflare/security-audit-skill, security-audit/SKILL.md, RECONNAISSANCE.md, HUNTING.md and VALIDATION-AND-REPORTING.md]. Use it for a selected security audit or a focused security question; routine code review does not automatically require a full audit workflow. General repository scope and persistence policy remain in [REPOSITORY-AUDIT.md](REPOSITORY-AUDIT.md).

## Boundary and result

- **Name the principal, controlled input and crossed boundary.** Trace the entry point, intended preventing control, affected resource and actual unauthorized result. Missing best practices, attacker-controlled data remaining under the same principal and hypothetical platform defaults do not by themselves establish a vulnerability. [cloudflare/security-audit-skill, security-audit/SKILL.md, HUNTING.md]
- **Trace the strongest preventing control before confirming impact.** Inspect shared helpers, framework behavior, upstream limits and the actual deployed configuration where available. An unknown policy attachment or unavailable environment is a blocker, not evidence that it is permissive. [cloudflare/security-audit-skill, security-audit/HUNTING.md, CLOUD-AND-DEPLOYMENT.md]
- **Separate evidence state from consequence.** A confirmed finding has a demonstrated source-grounded boundary violation; a rejected candidate states the control or fact that defeats it; an unresolved candidate states its exact missing evidence and a permitted validation plan. Do not attach a confirmed severity to an unresolved hypothesis. [cloudflare/security-audit-skill, security-audit/VALIDATION-AND-REPORTING.md]
- **Use P0 to P3, with confidence and likelihood separate.** Source critical maps to P0, high to P1, medium to P2 and low/informational to P3; choose the actual priority from the demonstrated consequence rather than copying an attack-class label. [cloudflare/security-audit-skill, security-audit/SKILL.md; repository severity convention]

## Coverage and prior work

- **Record actual coverage, including gaps.** For a comprehensive audit, track material combinations of entry surface, trust boundary, subsystem and applicable attack class. Include sibling paths, lifecycle modes, excluded surfaces, checks completed and unresolved work. A broad title or many scanner hits do not prove full coverage. [cloudflare/security-audit-skill, security-audit/RECONNAISSANCE.md]
- **Re-read current source before reusing a prior result.** Compare current code and relevant conditions, not merely an old source reference. A rejected claim suppresses only the same unchanged failed claim; deferred or blocked work never counts as completed coverage. [cloudflare/security-audit-skill, security-audit/SKILL.md]
- **Deduplicate by the defect mechanism.** Repeated observations of one root cause share one finding; distinct defects in the same function remain separate. State which entries were merged and why when it matters to coverage. [cloudflare/security-audit-skill, security-audit/VALIDATION-AND-REPORTING.md]
- **Use a fresh verifier for a material replacement in a selected full audit.** A stronger verdict or changed cause, input, result, impact or priority needs independent review by someone who did not hunt, validate or propose that replacement. If independence or decisive evidence is unavailable, retain the unresolved candidate and state that the audit is incomplete. Wording and line-number corrections do not require a new workflow. [cloudflare/security-audit-skill, security-audit/VALIDATION-AND-REPORTING.md]

## Execution and artifacts

- **Source inspection is read-only; target-controlled execution needs its own authorization and boundary.** The source permits sandboxed validation, but this repository permits no tests or builds unless the user asks. Do not turn a source sample into permission to contact a deployment, consume paid quota, stress shared infrastructure or execute repository code. Missing runtime proof remains a stated limitation. [cloudflare/security-audit-skill, security-audit/SKILL.md, VALIDATION-AND-REPORTING.md; user standing rules]
- **Keep plain audits stateless.** The source's full mode creates report and ledger artifacts; the repository's existing rule persists only selected artifacts or approved decisions. Use a requested artifact format when authorized, without importing the source harness, validator scripts, schema or unrelated numerical limits. [cloudflare/security-audit-skill, security-audit/SKILL.md; REPOSITORY-AUDIT.md]
- **Use the existing control owners.** Input and filesystem controls are in [secure-coding](https://github.com/Quegenx/agent-skills/blob/main/skills/engineering/secure-coding/SKILL.md); browser boundaries in [secure-coding BROWSER-BOUNDARIES.md](https://github.com/Quegenx/agent-skills/blob/main/skills/engineering/secure-coding/BROWSER-BOUNDARIES.md); tool action binding in [agent-harness](https://github.com/Quegenx/agent-skills/blob/main/skills/ai-agents/agent-harness/TOOLS.md#action-binding). [cloudflare/security-audit-skill, security-audit/ATTACK-CLASSES.md, AI-AND-LLM.md]

## Prove it

Every confirmed finding names a principal, reachable input, failed boundary, preventing controls examined, observed consequence and narrow correction. Unresolved candidates have explicit blockers without confirmed severity; coverage includes unread and excluded paths; current source supports reused results; material replacements have fresh verification or remain unresolved; only authorized execution and artifacts occurred. [cloudflare/security-audit-skill, security-audit/VALIDATION-AND-REPORTING.md]
