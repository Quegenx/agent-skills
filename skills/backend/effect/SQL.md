# SQL

`effect/sql` gives one `SqlClient` for every database; a driver package such as `@effect/sql-sqlite-node` or `@effect/sql-pg` supplies the layer. Domain models are `Model.Class` (from `effect/schema`), which derives the database and JSON shapes from one field list. Beta-era examples import from `effect/unstable/sql`; that path was removed in `4.0.0-rc.118`, so import from `effect/sql`. The modules stay tagged `@stability unstable`.

## Wiring

- **Imports:**

```ts
import { SqliteClient, SqliteMigrator } from "@effect/sql-sqlite-node"
import { Model } from "effect/schema"
import { SqlClient, SqlModel, SqlSchema } from "effect/sql"
```

  Modules in `effect/sql`: Migrator, SqlClient, SqlConnection, SqlError, SqlModel, SqlResolver, SqlSchema, SqlStream, Statement.
- **The client layer picks the database.** `const SqlLayer = SqliteClient.layer({ filename: ":memory:" })`; swap it for `@effect/sql-pg`, `@effect/sql-mysql2` and so on without changing the rest of the code.
- **Combine client and migrations so everything above sees a migrated database:** `const SqlLive = MigratorLayer.pipe(Layer.provideMerge(SqlLayer))`.
- **Wrap data access in a service** so the app depends on `Groups`, not on the database, and end the service layer with `.pipe(Layer.provide(SqlLive))`, keeping the wiring out of the main entrypoint.
- **Or split for tests:** `Users.layerNoDeps` only requires a `SqlClient`, so entrypoints and tests decide how the database is provided; `Users.layer: Layer.Layer<Users> = this.layerNoDeps.pipe(Layer.provide(MigratorLayer.pipe(Layer.provideMerge(SqlLayer))), Layer.orDie)` requires nothing.
- **Database and encoding failures are defects in the example service** (`Effect.orDie`), so its interface carries only domain errors.

## Models

- **`Model.Class<Group>("Group")({...})` is the single source of truth** for these variants: `Group`, `Group.insert`, `Group.update` for the database; `Group.json`, `Group.jsonCreate`, `Group.jsonUpdate` for JSON APIs. Use it when the database shape differs from the public API: generated ids, audit timestamps, nullable columns, private fields, different encodings per boundary.
- **Field helpers:**
  - `Model.UuidV4Insert(GroupId)`: a UUID v4 primary key generated by the application on insert (also `UuidV7Insert`, `UuidV4BytesInsert`).
  - `Model.GeneratedByDb`: in `select` and `json`, omitted from `insert`, `update`, `jsonCreate`, `jsonUpdate`. `GeneratedByApp` exists too.
  - `Model.Sensitive`: in database variants, omitted from all JSON variants.
  - `Model.FieldExcept(["update", "jsonUpdate"])` removes a field from those variants; `Model.FieldOnly(["select", "insert"])` keeps it only there (for example internal notes never exposed through JSON).
  - `Model.Field({ select: Schema.Int, json: Schema.Int })`: full control per variant.
  - `Model.FieldOption`: database variants accept `null`; JSON variants also accept a missing key.
  - `Model.DateTimeInsert`, `Model.DateTimeUpdate` (stored as strings, which suits SQLite), and `DateTimeInsertFromDate`, `DateTimeInsertFromNumber`, `DateTimeUpdateFromDate`, `DateTimeUpdateFromNumber`.
  - `Model.BooleanSqlite` (`0 | 1` in the database, `boolean` in JSON), `JsonFromString`, `optionalOption`, `Override`.
- **`Group.insert.makeEffect({ name, slug, notes: null })`** fills the generated id and timestamps from the Effect clock, so tests control them with `TestClock`.
- **At an HTTP boundary** use `User.json` for responses and `User.jsonCreate` / `User.jsonUpdate` for payloads (HTTP.md).

### Model variants example

The schema integration guide uses this original declaration:

```ts
  class Group extends Model.Class<Group>("Group")({
    id: Model.UuidV4Insert(GroupId),
    name: Schema.NonEmptyString,
    slug: Schema.NonEmptyString.pipe(Model.FieldExcept(["update", "jsonUpdate"])),
    notes: Schema.NullOr(Schema.String).pipe(Model.FieldOnly(["select", "insert"])),
    memberCount: Model.Field({ select: Schema.Int, json: Schema.Int }),
    createdAt: Model.DateTimeInsert,
    updatedAt: Model.DateTimeUpdate
  }) {}
```

`Model.Date` is also available alongside the field helpers above. [Existing SCHEMA-INTEGRATIONS.md, SQL and Model]

## Repositories

- **Derive CRUD from the model:**

```ts
SqlModel.makeRepository(Group, { tableName: "groups", spanPrefix: "Groups", idColumn: "id" })
```

  It gives insert, update, findById and delete, each using the matching variant schema. Dialect differences such as `returning` support are handled inside.
- **`findById` fails with `NoSuchElementError`.** Map it: `Effect.catchTags({ NoSuchElementError: () => new GroupNotFound({ id }), SchemaError: Effect.die, SqlError: Effect.die })`.
- **Soft delete:** pass `softDeleteColumn`; reads then ignore soft-deleted rows and delete updates that column instead of removing the row.
- **`SqlModel.makeResolvers`** builds batched request resolvers for insert, insert-void, find-by-id and delete.

The schema integration guide shows the domain-error mapping in full:

```ts
  repo.findById(id).pipe(Effect.catchTags({
    NoSuchElementError: () => new GroupNotFound({ id }),
    SchemaError: Effect.die,
    SqlError: Effect.die
  }))
```

## Queries

- **`sql` is a tagged template; interpolations become parameters:** `` sql`SELECT * FROM users WHERE name LIKE ${pattern} OR email LIKE ${pattern}` ``. Get it with `const sql = yield* SqlClient.SqlClient`.
- **Decode ad hoc queries with `SqlSchema`:**

```ts
const listAll = SqlSchema.findAll({
  Request: Schema.Void,
  Result: Group,
  execute: () => sql`SELECT * FROM groups ORDER BY createdAt`
})
// listAll()
```

- **`SqlSchema` helpers:** `findAll` (empty result allowed), `findNonEmpty` (fails with `NoSuchElementError` when empty), `findOne` (first row, `NoSuchElementError` when none), `findOneOption` (returns `Option`). Each takes `{ Request, Result, execute: (request: Req["Encoded"]) => Effect<ReadonlyArray<unknown>, E, R> }` and returns `(request: Req["Type"]) => Effect<..., E | Schema.SchemaError, ...>`: it encodes the request before `execute` and decodes the rows.
- **Statement helpers on `sql`:** `sql(value: string)` for an `Identifier`; `sql.unsafe(sql, params?)`; `sql.literal`; `sql.in(values)` or `sql.in(column, values)`; `sql.insert(record | records)`; `sql.update(value, omit?)` (one row); `sql.updateValues(rows, alias)` (not supported in SQLite); `sql.and`, `sql.or`; `sql.csv([prefix,] values)` for `ORDER BY` and `GROUP BY`; `sql.join`; `sql.onDialect({ sqlite, pg, mysql, mssql, clickhouse })`; `sql.onDialectOrElse({ orElse, ... })`.
- **A `Statement<A>` is an `Effect<ReadonlyArray<A>, SqlError>`** plus `raw`, `withoutTransform`, `stream: Stream<A, SqlError>`, `values`, `valuesUnprepared`, `unprepared`, and `compile(withoutTransform?)` returning `[sql, params]`.
- **`SqlClient` members:** `safe`, `withoutTransforms()`, `reserve` (a scoped `Connection`), `driver` (the package name without `@effect/sql-`, such as `"pg"`, `"pglite"`, `"sqlite-node"`), `withTransaction`, `transactionService`, `afterCommit`, `reactive(keys, effect)` returning a `Stream`, `reactiveMailbox`.
- **Batch concurrent lookups with `SqlResolver`,** which keeps batches separated by the active transaction connection: `ordered` (results map to requests in order, so lengths must match, else `ResultLengthMismatch`), `grouped`, `findById` (missing ids fail with `NoSuchElementError`), `request`.
- **Large result sets:** `SqlStream` turns driver cursors into a `Stream` so rows are processed incrementally, not all held in memory.
- **`SqlClient.SafeIntegers`** opts in to safe integer handling; it defaults to `false`.

## Transactions

- **`sql.withTransaction(effect)`** runs every query in the effect in one transaction: top-level begin, savepoints for nested calls, commit on success, rollback on failure or interruption.
- **`sql.afterCommit(effect)` signals committed changes** (waking workers, invalidating caches, notifying subscribers). It runs once the outermost transaction commits, or immediately and interruptibly when none is open. It is discarded on rollback, on a failed `COMMIT` and for rolled-back savepoints.
- **Gotchas of `afterCommit`:**
  - Callbacks are lost if the process exits first or the `COMMIT` outcome is unknown; work that must happen belongs in a table written in the same transaction.
  - After `COMMIT` they run uninterruptibly and `withTransaction` waits for them; keep them short and fork long work.
  - Registering after the transaction has ended is a defect.
  - Transactions that don't go through `makeWithTransaction`, such as `@effect/sql-sqlite-do`'s, run callbacks immediately.

## Migrations

- **Migrations are effects keyed `<id>_<name>` that run once, in id order:**

```ts
const MigratorLayer = SqliteMigrator.layer({
  loader: SqliteMigrator.fromRecord({
    "0001_create_groups": Effect.gen(function*() {
      const sql = yield* SqlClient.SqlClient
      yield* sql`CREATE TABLE groups (...)`
    })
  })
})
```

  A real application keeps each migration in its own file and loads them with `SqliteMigrator.fromFileSystem`.
- **What the migrator does:** records completed ids in a migrations table (created when needed), runs only pending migrations in a transaction, detects duplicate ids, treats concurrent runs as locked, and can dump the schema afterwards. `MigratorOptions = { loader, schemaDirectory?, table? }`.
- **Loaders:** `fromRecord`, `fromGlob` (a record of dynamic imports, files `<id>_<name>.js|.ts|.mjs|.mts`), `fromBabelGlob`, `fromFileSystem(dir)`. `fromFileSystem` needs `FileSystem` and `Path`; on Windows use a platform-aware `NodePath.layer`, because the core `Path.layer` is POSIX and drops drive letters.
- **Driver migrators** (`PgMigrator`, `SqliteMigrator`, ...) re-export `effect/sql/Migrator` and add `run` and `layer`, which runs migrations during layer construction. `PgMigrator` schema dumps use `pg_dump` and need child process, file system and path services.

## Errors

- **`SqlError` wraps a reason;** its `message`, `cause` and `isRetryable` come from the `SqlErrorReason`:

| Reason | Retryable |
|---|---|
| `ConnectionError` | yes |
| `DeadlockError`, `SerializationError`, `LockTimeoutError`, `StatementTimeoutError` | yes |
| `AuthenticationError`, `AuthorizationError`, `SqlSyntaxError` | no |
| `UniqueViolation` (carries the constraint), `ConstraintError` | no |
| `UnknownError` | no |

  Guards: `isSqlError`, `isSqlErrorReason`; `classifySqliteError` maps SQLite errors.

## Drivers

- **Packages:** `@effect/sql-pg` (PostgreSQL, native wire-protocol driver), `sql-pglite` (PGlite WASM Postgres for browser, Node and Bun), `sql-mysql2`, `sql-mssql` (`tedious`), `sql-sqlite-node` (built-in `node:sqlite`), `sql-sqlite-bun` (`bun:sqlite`), `sql-sqlite-wasm` (`@effect/wa-sqlite`), `sql-sqlite-react-native` (`@op-engineering/op-sqlite`), `sql-sqlite-do` (Durable Objects SQLite), `sql-d1` (Cloudflare D1), `sql-libsql` (`@libsql/client`), `sql-clickhouse` (`@clickhouse/client`). Driver versions match the `effect` version.
- **Postgres layers:** `PgClient.layer(config): Layer<PgClient | SqlClient, SqlError>` provides both the driver tag and the generic `SqlClient`; `PgClient.layerConfig(Config.Wrap<PgPoolConfig>)`; `PgClient.layerFrom(acquire)` (adds `Reactivity.layer`).
- **`PgClientConfig`:**
  - `url: Redacted`; `password` is static or an Effect evaluated per connection attempt.
  - `multiplex` pipelines queries from many fibers on each pooled connection; transactions, streams and listeners still reserve one. `multiplexConcurrency` defaults to `32`.
  - `prepare` caches prepared statements by name, on by default; disable it for poolers that can't keep named statements between queries. `preparedStatementCacheSize` defaults to `100`; `maxMessageSize` to 16 MiB.
  - `transformResultNames`, `transformQueryNames`, `transformJson`, `types`.
  - `PgPoolConfig` adds `idleTimeout`, `maxConnections`, `minConnections`, `connectionTTL`.
- **Postgres session defaults:**

```ts
PgClient.layer({
  url: Redacted.make("postgres://..."),
  startupParameters: { statement_timeout: "5s", search_path: "app, public" },
  startupOptions: "-c lock_timeout=1000"
})
```

  Reserved names: `user`, `database`, `replication`, `options`. `application_name` precedence: `applicationName`, then `startupParameters.application_name`, then the URL, then `"@effect/sql-pg"`.
- **Postgres types:** unknown OIDs decode as UTF-8 text (enums read as strings). A codec failure while reading a row is fatal to the connection, not only the query. Binary user-defined types (composite, PostGIS, pgvector) need a codec: `PgTypes.register(oid, codec)`, or `PgTypes.makeRegistry()` plus `types.register(oid, codec, { arrayOid })` passed as `types`. Look OIDs up in `pg_type` at startup; they are assigned per database.
- **PGlite listen/notify:** `const notifications = yield* sql.listen("events")` is a scoped subscription that returns once the listener is installed; `yield* sql.notify("events", "ready")`; read with `Queue.take(notifications)`.
- **`SqliteClientConfig` (sqlite-node):** `filename`, `readonly?`, `prepareCacheSize?`, `prepareCacheTTL?`, `disableWAL?`, `busyTimeout?` (defaults to 5 seconds; waiting blocks the event loop because `node:sqlite` is synchronous), `transformResultNames?`, `transformQueryNames?`.
- **`KeyValueStore.layerSql({ table? })`** stores key-values in a SQL table (PLATFORM.md).

## Porting from v3

- **`@effect/sql`** is now `effect/sql` (import the barrel or `effect/sql/<Module>`).
- **`Model.Class`** moved to `effect/schema/Model`; variants are still `select`, `insert`, `update`, `json`, `jsonCreate`, `jsonUpdate`.
- **`SqlSchema.single`** is `SqlSchema.findOne`; empty results use `Cause.NoSuchElementError`, schema failures `Schema.SchemaError`. `SqlSchema.void` and `SqlResolver.void` remain; the resolver returns a `RequestResolver` synchronously and runs through `SqlResolver.request`.
- **`@effect/sql-drizzle` is removed:** import `PgDrizzle` from `drizzle-orm/effect-postgres`, define an application service tag and compose with `PgClient.layer`.
- **`@effect/sql-kysely` is removed:** use native `kysely#Kysely` and wrap promise execution with `Effect.tryPromise`.
- **`sql-sqlite-node` moved from `better-sqlite3` to `node:sqlite`.**

## Anti-patterns

- **Importing from `effect/unstable/sql`** or `@effect/sql`.
- **Building SQL by string concatenation** instead of interpolating into the `sql` template (interpolations are parameters).
- **Writing separate insert, update and JSON schemas by hand** when one `Model.Class` derives them.
- **Doing must-happen work in `afterCommit`;** write it to a table in the same transaction.
- **Hard-coding Postgres type OIDs.**
- **Using core `Path.layer` with `fromFileSystem` on Windows.**

## Prove it

The service runs against `SqliteClient.layer({ filename: ":memory:" })` with the migrator merged in, a `findById` for a missing id surfaces the domain error rather than `NoSuchElementError`, a failure inside `withTransaction` leaves no rows behind, and a second migrator run applies nothing new.
