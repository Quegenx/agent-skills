# Extension to Functions migration

From [firebase/agent-skills, extension-to-functions-codebase/SKILL.md; references/configuration-migration.md; references/signature-mapping.md; references/destructuring-shim.md], corrected against firebase-functions source and the Firebase upgrade guide.

## Inventory the actual Extension

[firebase/agent-skills, extension-to-functions-codebase/SKILL.md]

- Inspect the extension manifest, resources, trigger handlers, parameters, secrets, required APIs/roles and lifecycle operations.
- Separate reusable application logic from extension-specific configuration and event signatures.
- Produce the requested standalone Functions codebase or package using the actual dependency/runtime contract. Do not preserve a second implementation without a compatibility requirement.
- Keep API/role declarations and lifecycle effects visible in the reviewed migration.

## Configuration names and timing

[Functions params source](https://github.com/firebase/firebase-functions/blob/master/src/params/index.ts)

- Use supported parameter definitions such as defineString, defineBoolean, defineInt, defineSecret and defineJsonSecret for their respective values.
- The source named defineNumber and defineJSON; they are not the exported parameter names. JSON secret support is defineJsonSecret, not a universal ordinary JSON-parameter replacement.
- defineFloat is marked internal in the inspected source; do not promote it as a stable public replacement just because an autogenerated reference lists it.
- Distinguish deployment-time parameter expressions from runtime secret access. Do not read secret values during deployment evaluation.
- Old functions.config usage needs the installed major-version migration path; current v7 source removes it. [Functions v1 reference](https://github.com/firebase/firebase-functions/blob/master/_autodocs/api-reference/v1.md)

## Triggers, declarations and lifecycle

[firebase/agent-skills, extension-to-functions-codebase/references/signature-mapping.md; references/destructuring-shim.md]

- Translate the actual trigger signature and event data, including before/after and event identity where needed. Do not mechanically preserve a v1 argument shape in a v2 handler.
- Current requiresRole/requiresAPI and lifecycle registration are real supported source features; inspect installed exports and declarations rather than deleting them as presumed inventions. [Functions options](https://github.com/firebase/firebase-functions/blob/master/_autodocs/api-reference/options.md), [lifecycle](https://github.com/firebase/firebase-functions/blob/master/_autodocs/api-reference/lifecycle.md)
- Lifecycle hooks are effects, not harmless metadata. Preserve the intended first-deploy versus redeploy behavior and supported single-registration constraints.
- addV1Compat is an available compatibility route, but keep a shim only where compatibility is needed; point to direct replacement rather than making two permanent paths.

## Concurrency and shared state

[Functions concurrency](https://firebase.google.com/docs/functions/manage-functions#allow-concurrent-requests), [upgrade guide](https://firebase.google.com/docs/functions/2nd-gen-upgrade)

- 80 is the default concurrency, not the maximum. The documented configurable range is 1 to 1000, subject to CPU eligibility.
- Concurrency requires at least one full CPU; fractional CPU or the documented low-memory gcf_gen1 case disables it.
- Audit request-mutated globals when moving from one request per instance to concurrent requests.
- The source/old table treated 80 as a ceiling. Do not use a low-concurrency compatibility setting as the long-term fix for shared-state races.
- Tune minimum/maximum instances, concurrency and downstream connection demand together; a maximum-instance cap can cause dropped requests.

## Prove it

Each manifest capability has a documented destination, installed exports match parameter names, trigger/lifecycle identity is preserved, compatibility shims have an actual requirement and concurrent requests do not rely on shared mutable request state.
