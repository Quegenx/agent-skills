# Maintain a library of product films

Reusable product-film foundations from the supplied video/references/code-rendered-product-films.md. Use for repeated walkthroughs, feature films or account-specific variants that share one product. Keep [engine selection](ENGINES.md), the [studio gates](SKILL.md#the-gates), capture, audio and review with their existing owners. [video, references/code-rendered-product-films.md, When to Use This Format and Core Idea]

## Share the foundation

[video, references/code-rendered-product-films.md, Set Up a Private Video Repo and Capture the Real UI]

- Keep a shared UI kit, captured screens and states, overlays, end card, product truths, fictional cast and music beds together. A new film draws on that foundation rather than quietly recreating the same app differently.
- Capture from a seeded local product using a consistent fictional cast. Preserve rendered UI and a reference image; derive a missing state only from the actual component source. Use the existing [app recording procedure](https://github.com/Quegenx/agent-skills/blob/main/skills/videos/asset-prep/APP-RECORDING.md) for capture setup and cleanup.
- Audit snapshots for real names, email addresses, avatars, API keys, timezone and locale before retaining or sharing them. A capture is not cleared merely because its visible main user is fictional.
- Maintain a per-film record of script, timings, chapters, claim checks, app/docs discrepancies and approved deliverables. Keep shared fixes distinguishable from film-specific changes. The source's branch/worktree lifecycle is excluded from this skill.

## Keep every film true to the product

[video, references/code-rendered-product-films.md, Write the Script and Review Before Anyone Sees It]

- Read the feature's docs and app source. Check labels, buttons, steps and feature claims against implementation; keep supported platforms, trial terms and early-access limitations in the shared brief.
- If docs and UI disagree, record the discrepancy with the film. The source follows the UI and says to fix docs afterward; a film request does not authorize an unrelated documentation change. Preserve the discrepancy for its owner.
- Check retained screens again when the product changes. Reusing a kit does not prove it still matches the feature being described.
- Review contact sheets at readable size and verify an automated judge's alleged defect against actual frames. A model's report is a lead, not proof that the glitch exists.

## Produce and hand over

[video, references/code-rendered-product-films.md, Audio, Render, Review Before Anyone Sees It and Mistakes to Skip]

- Limit workers on shared machines and stop only processes you own by PID. Keep other agents' renders intact.
- Deliver the finished assets with their claim checks and discrepancy record. Surface renderer or host errors instead of treating a missing output as success. Publishing still follows the user's authorization.
- Report which visual and audio checks were actually possible. The source says agents cannot listen; that is not a universal capability limit. If the available tools cannot inspect audio, retain an explicit ear-check handoff.
- Keep source taste differences explicit: it proposes body text at least 20px at 1080p, captions settled at least 0.4s before their click and a -1.2dBTP mix. These are source choices; the existing shotlist, caption and sound-pass values remain the defaults until the brief selects an alternative. [video, references/code-rendered-product-films.md, Starter Taste Rules and Audio; make-video, SKILL.md; sound-pass, SKILL.md]

## Prove it

[video, references/code-rendered-product-films.md, Review Before Anyone Sees It and Mistakes to Skip]

Every depicted feature has a code source, every person and record is fictional, retained captures pass the leak review, the approved assets are present, and discrepancies and unperformed checks accompany delivery. A reused kit is a production method, not evidence for the source's unverified third-or-fourth-film payback claim. Frame rendering and live app capture remain separate workflows.
